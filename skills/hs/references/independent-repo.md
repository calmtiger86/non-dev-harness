이 파일은 /hs 1단계에서 현재 폴더가 더 큰 git 저장소 안에 있고, 사용자가 "이 폴더를 독립 기록으로 시작"을 골랐을 때 읽습니다.

# 상위 저장소 안에서 독립 기록 시작하기

## 1단계에서 기억해 둘 값
- 현재 폴더에서 `-C` 없이 실행한 `git rev-parse --show-prefix` 출력(<상위 기준 경로>, 예: `Dev claude/내 새 프로젝트/`)과 `git rev-parse --show-toplevel` 출력(<상위 최상위>, 예: `/Users/me/Desktop`)을 6-2까지 그대로 씁니다. 6-1 git init 뒤에 다시 구하면 값이 이 폴더 기준으로 바뀌므로 다시 구하지 않습니다.
- 상위 저장소가 이미 이 폴더 파일을 기록 중인지 현재 폴더에서 `-C` 없이 `git ls-files -- .`로 봅니다. 결과가 있으면 "상위 저장소가 이미 이 폴더 파일 N개를 기록 중이라 `.gitignore`만으로는 상위 기록에서 빠지지 않습니다. 빼려면 상위 저장소에서 `git rm -r --cached`로 기록에서 빼야 합니다"라고 안내만 합니다. 상위 저장소에는 쓰지 않습니다(그 일은 사용자가 상위 저장소에서 직접 합니다).
- 상위 저장소의 `.gitignore`에 이 폴더를 넣어 상위 기록에서 뺄지 여기서 묻기만 합니다(넣기 / 넣지 않기). 실제로 넣는 것은 6-2에서 한 번만 합니다.

## 상위 `.gitignore`에 넣을 줄 (6-2)
- 파일: `<상위 최상위>/.gitignore` (이 폴더의 `.gitignore`가 아님). 있는지는 Bash(`ls` 등)로 보지 않고 Read 도구로 열어 봅니다. 열리면 Edit로 파일 끝에 한 줄 덧붙이고, 파일이 없다는 오류가 나면 Write로 그 한 줄만 담아 새로 만듭니다.
- 줄 모양: `/` + <상위 기준 경로>. 앞에 `/`가 있어야 상위 저장소의 그 위치 하나만 뺍니다(없으면 상위 저장소 어디서든 같은 이름 폴더를 모두 뺍니다). <상위 기준 경로>는 `/`로 끝나므로 줄도 `/`로 끝납니다. 예: `/Dev claude/내 새 프로젝트/`
- gitignore 문법 때문에 경로의 각 이름에서 다음 글자 앞에 `\`를 붙입니다: 이름 안의 `*`, `?`, `[`, `\`, 이름 맨 앞의 `#`·`!`, 이름 끝의 공백. 이름 중간의 공백은 그대로 둡니다. 예: `내 #1 폴더`는 그대로, `#메모`는 `\#메모`, `[임시]`는 `\[임시]`.
- 이 줄은 5단계 미리보기의 "실행할 동작"에 "상위 저장소 `.gitignore`(<상위 최상위>/.gitignore)에 넣을 줄: `/…/`"로 보여 줍니다.
- 상위 저장소에는 커밋하지 않습니다. 완료 안내에 "상위 저장소(<상위 최상위>)의 `.gitignore` 변경은 커밋하지 않았습니다. 상위 저장소에서 따로 기록해 주세요"를 한 줄 붙입니다.

## 사용자 정보 (6-1 뒤)
- 4단계의 `git config --get user.name`·`user.email` 확인은 git init 전이라 상위 저장소 설정까지 읽습니다. 상위 저장소에만 있는 이름은 새 저장소에 쓰이지 않으므로, 6-1 init과 확인이 끝난 뒤 현재 폴더에서 `-C` 없이 두 명령을 다시 실행하고, 비어 있으면 그때 묻습니다(6-4에서 `--local`로 설정).
