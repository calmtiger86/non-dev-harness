# 인터뷰 가이드 (상세)

## 가설-확인 인터뷰 방식

interview-me 패턴: 가설을 먼저 제시하고 사용자가 확인/수정하는 방식.

이 가이드는 새로 만들기 모드의 인터뷰에 씁니다. 덧붙이기·업데이트·업그레이드 모드에서 무엇을 묻는지는 `existing-harness-modes.md`의 각 모드 절을 따릅니다.

선택지 질문 도구(AskUserQuestion)가 있으면 폴더 이름, 파일, 앞 답에서 추론한 값을 첫 선택지로 두고, 직접 입력은 도구가 붙여 주는 기타(Other)로 받습니다. 후보가 하나뿐이면 둘째 선택지는 "다른 이름으로 할게요"처럼 직접 입력을 안내하는 항목으로 둡니다(도구는 선택지가 둘 이상이어야 합니다). 도구가 없으면 번호 목록 글로 묻습니다.

### 진행 순서

1. 폴더명에서 프로젝트 이름 추론 → "프로젝트 이름이 '[폴더명]'이 맞나요?"
2. 폴더 내 파일을 읽어 프로젝트 유형 추론 → "이 프로젝트는 [추론]인 것 같은데 맞나요?"
3. 대상 → "누구를 위한 프로젝트인가요?" (선택지 예: 개인 사용 / 팀·동료 / 고객·외부 사람, 그 밖은 기타)
4. 사용 도구 → package.json, requirements.txt 등으로 추론해 선택지로 제안. 단서가 없으면 "어떤 도구나 프로그램을 쓰시나요? 없거나 모르면 '없음'도 괜찮아요"
5. 언어는 기본 한국어 → 영어로 대화 중이면 영어로 전환

### 종료 조건

5개 항목(이름, 하는 일, 대상, 도구, 언어)이 채워지면 인터뷰를 끝냅니다. 파일이나 앞 답에서 이미 알 수 있는 항목도 건너뛰지 않고, 추론값을 첫 선택지로 두어 확인받습니다. 특히 2번(무엇을 하는 프로젝트인가요?)은 이름 답에서 짐작할 수 있어도 꼭 확인합니다.

### 비개발자 배려

- "기술 스택"이라는 용어 대신 "어떤 도구나 프로그램을 쓰시나요?"
- "없음/모름"은 항상 유효한 답변
- 추가 질문은 사용자가 원할 때만
