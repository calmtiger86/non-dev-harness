# 이미 있는 CLAUDE.md나 하네스를 다루는 모드

공통: 기존 CLAUDE.md는 템플릿 구조에 맞추지 않습니다. 이 파일에서 정한 곳 말고는 섹션의 순서·제목·내용을 그대로 두고, 100줄을 넘어도 기존 내용을 줄이지 않습니다. 이미 있는 기록 파일은 다시 만들지 않습니다. 빠진 기록 파일을 템플릿으로 만들 때 `{{PROJECT_NAME}}`은 CLAUDE.md의 첫 `#` 제목에서 가져옵니다.

## 덧붙이기 (표식 없는 CLAUDE.md가 있음)

- 기존 CLAUDE.md 내용은 한 글자도 바꾸지 않습니다. 맨 앞에 표식 한 줄을 새로 넣고, 파일 끝에 템플릿의 `## 하네스 파일 안내`부터 `## 변경이력`까지를 덧붙입니다(`## 프로젝트 정보`는 넣지 않습니다).
- 기존 CLAUDE.md에 같은 제목(`## 원칙`, `## 프로젝트 규칙`, `## 변경이력` 등)이 이미 있으면 그 섹션은 덧붙이지 않고 알립니다.
- 100줄 기준은 덧붙인 부분에만 적용하며, 기존 내용을 줄이거나 요약하지 않습니다.
- 다른 기록 파일은 없는 것만 만듭니다.
- 인터뷰: 기록 파일 제목에 쓸 프로젝트 이름만 확인합니다.

## 업데이트 (v2 표식)

- CLAUDE.md는 `## 프로젝트 정보` 섹션만 Edit로 고칩니다. 그 섹션이 없으면 새로 만들지 묻고, 만든다면 첫 `##` 섹션 바로 위에 넣습니다.
- 빠진 기록 파일만 템플릿으로 만들고, `.gitignore`에 빠진 줄이 있으면 추가를 제안합니다. 다른 섹션과 기존 기록 내용은 건드리지 않습니다.
- 인터뷰: 지금 `## 프로젝트 정보`의 값을 보여 주고 바꿀 항목만 묻습니다. 섹션이 없고 새로 만들기로 했으면 SKILL.md 인터뷰의 2~5번을 묻습니다.

## 업그레이드 (v1에서 v2로)

실제 v1 프로젝트의 CLAUDE.md는 템플릿과 구성이 많이 다릅니다. 템플릿 구조를 강요하지 않고, 기존 기록 내용은 제목 줄을 빼고 한 줄도 바꾸지 않으며, 아래만 합니다. 인터뷰는 하지 않습니다.

**도구 쓰는 법 (업그레이드 전체).** 조사(파일 목록, 첫 줄, 섹션 제목, `.gitignore` 내용)는 Read·Grep·Glob 도구로 합니다. 파일 내용 변경(일지 첫 줄, CLAUDE.md 표식·표·섹션·변경이력 행, `.gitignore`)은 Edit 도구로만 합니다(`.gitignore`가 없으면 Write 도구로 새로 만듦). Bash는 명령 하나씩만 씁니다: `git ls-files --error-unmatch "MEMORY.md"`, `git mv "MEMORY.md" "JOURNAL.md"`(git이 추적하지 않으면 하네스 루트에서 `mv "MEMORY.md" "JOURNAL.md"` 단독), `git add -- …`, SKILL.md 6-6의 검사·커밋 스크립트 한 줄. `cd`·`;`·`&&`·`sed`·`cat >`·`printf >>`·`echo`·heredoc을 쓰지 않습니다.

- 하네스 형식 MEMORY.md(첫 줄이 `— 메모리`로 끝남)의 이름을 JOURNAL.md로 바꿉니다. 첫 줄이 그 형식이 아니면 사용자가 직접 만든 파일일 수 있으므로 바꾸지 않고 알립니다. JOURNAL.md가 이미 있으면 이름을 바꾸지 않고 알립니다. 하네스 루트에서 `git ls-files --error-unmatch "MEMORY.md"`가 성공하면(git이 추적하던 파일) `git mv "MEMORY.md" "JOURNAL.md"`, 실패하거나 git 저장소가 아니면 `mv`를 씁니다. 일지가 상한(세션 로그 5개 등)을 넘었어도 이름만 바꾸고, 정리는 다음 /co 때 묻도록 둡니다.
- 일지 제목 줄(첫 줄)이 `— 메모리`로 끝나면 Edit 도구로 그 부분만 `— 작업 일지`로 바꿉니다.
- Edit 도구로 CLAUDE.md 첫 줄 표식을 `<!-- non-dev-harness:v2 -->`로 바꿉니다.
- `## 하네스 파일 안내` 표가 있으면 Edit 한 번으로 `| MEMORY.md |`라는 글자만 `| JOURNAL.md |`로 바꿉니다. 그 행의 설명 칸은 바꾸지 않습니다. 그 밖에 사용자가 쓴 `MEMORY.md` 언급(변경이력 행 등)은 목록으로 보여 주고 바꿀지 묻습니다.
- 없는 v2 섹션(`## 기록 파일 다루는 법`, `## 원칙`)만 템플릿에서 가져와 덧붙입니다. `## 프로젝트 규칙`이 있으면 그 바로 위에, 없으면 `## 변경이력` 바로 위에, 둘 다 없으면 파일 끝에 넣습니다. 기존 섹션은 옮기지 않습니다.
- `## 변경이력` 표가 있으면 Edit 도구로 표 마지막 행 뒤에 오늘 날짜의 v2 업데이트 행을 하나 추가하고, 없으면 건너뜁니다.
- 빠진 기록 파일(ERROR.md, ISSUE.md, WIKI.md 등)은 템플릿으로 만듭니다. JOURNAL.md와 하네스 형식 MEMORY.md가 모두 없으면 JOURNAL.md도 템플릿으로 만듭니다. 이미 있는 파일은 건드리지 않습니다.
- `.gitignore`는 Read로 보고 Edit로 고칩니다. v1 줄이 남아 있으면 따로 묻습니다. `*.key` 줄은 Keynote 발표 파일까지 백업에서 빠지게 하므로 지울지 묻고, `.env*` 줄은 `.env.example`까지 빼므로 `.env`, `.env.*`, `!.env.example` 세 줄로 바꿀지 묻습니다. 이 두 질문 말고는 기존 `.gitignore` 줄을 지우거나 순서를 바꾸지 않습니다.
- `## 토큰 절약 규칙` 섹션이 있으면 아래 v1 원문과 똑같은 줄만 지우자고 제안합니다. 지우는 이유는 이 컴퓨터의 개인 규칙이 아니라 "지금의 Claude Code가 기본으로 하는 일이라서"로 설명합니다. 질문 문구 예시: "`## 토큰 절약 규칙`의 6줄은 옛 v1이 넣은 문구이고, 지금의 Claude Code가 기본으로 하는 일이라 더는 필요 없습니다. 지울까요?" (지우기 / 그대로 두기). 사용자가 고치거나 더한 줄은 남기고, 남은 줄이 없을 때만 섹션 제목도 지웁니다. 섹션이 없으면 건너뜁니다.

- 커밋(SKILL.md 6단계): 이름을 바꾼 MEMORY.md는 `git add`에 넣지 않습니다(`git mv`가 이미 스테이징했습니다). MEMORY.md가 git이 추적하던 파일이었으면(`git mv`를 썼으면) "MEMORY.md"를 `git commit -- …` 경로에 넣어 이름 바꾸기가 기록되게 합니다. 커밋 메시지는 `hs: 하네스 v2 업데이트`입니다.
