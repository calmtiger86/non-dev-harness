# hs — 하네스 세팅

프로젝트의 세션 컨텍스트를 유지하기 위한 5개 파일과 git 기록 시스템을 세팅합니다.

## 언제 사용

- 새 프로젝트를 시작할 때 (최초 1회)
- 기존 프로젝트에 하네스를 추가할 때
- 하네스 설정을 다시 하거나 업데이트할 때

## 프로세스

### 1. 범위 선택

WHY: 프로젝트별 규칙과 전체 공통 규칙을 분리해야 충돌이 없다.

사용자에게 묻기:
- **프로젝트용** (현재 폴더): 이 프로젝트에만 적용
- **시스템 범용** (~/.claude/): 모든 프로젝트에 적용

시스템 범용 선택 시 경고: "글로벌 설정입니다. 모든 프로젝트에 영향을 줍니다."

프로젝트용 → 파일을 `./`에 생성. 시스템 범용 → `~/.claude/`에 생성.

### 2. 상태 감지

WHY: 기존 설정을 실수로 덮어쓰면 사용자 작업이 사라진다.

CLAUDE.md 파일 확인:
- `<!-- non-dev-harness:` 마커 있음 → "기존 하네스가 있습니다. 덮어쓸까요?"
- CLAUDE.md 있지만 마커 없음 → "기존 파일에 하네스 섹션을 추가할까요?" (마커는 반드시 파일 첫 줄에 삽입)
- CLAUDE.md 없음 → 신규 생성 진행

### 3. 인터뷰

WHY: 프로젝트 맥락을 알아야 적절한 규칙을 만들 수 있다.

가설-확인 방식으로 진행 (한 번에 1문 1답):

1. **프로젝트 이름**: 폴더명에서 추론하여 제안 → 확인/수정
2. **무엇을 하는 프로젝트인가요?**: 1-2문장 (예: "블로그를 운영합니다")
3. **누구를 위한 건가요?**: 대상 (예: "개인 사용", "고객용")
4. **사용 도구**: "어떤 도구나 프로그램을 쓰시나요?" — "없음/모름"도 유효한 답변
5. **선호 언어**: 기본값 한국어

95% 규칙: 사용자의 다음 3개 질문을 예측할 수 있으면 인터뷰 종료.

### 4. Git 초기화

WHY: 비개발자가 git을 잊어도 작업이 안전하게 기록되어야 한다.

git repo가 아닌 경우:
- "작업 기록 시스템을 켤까요?" (기본값: 예)
- 예 → `git init` + `.gitignore` 생성
- `.gitignore` 기본 내용: `.DS_Store`, `node_modules/`, `*.log`, `.env*`, `*.pem`, `*.key`, `credentials*.json`, `service-account*.json`, `.omc/`

GitHub 연결 (선택):
- "클라우드 백업(GitHub)에 연결할까요?" (거절 가능)
- 예 → `gh repo create` 안내

### 5. 파일 생성

WHY: 템플릿 기반 생성으로 일관된 구조를 보장한다.

`~/.claude/plugins/non-dev-harness/templates/` 에서 5개 템플릿을 읽어 `{{placeholder}}`를 치환한다:

- `CLAUDE.md.template` → CLAUDE.md
- `MEMORY.md.template` → MEMORY.md
- `ERROR.md.template` → ERROR.md
- `ISSUE.md.template` → ISSUE.md
- `WIKI.md.template` → WIKI.md

치환 전 입력 검증:
- 모든 치환 값에서 마크다운 헤딩(#), HTML 태그를 제거
- 각 값은 단일 행으로 제한 (줄바꿈 → 공백)
- 200자 초과 시 잘라내기

치환 변수:
- `{{PROJECT_NAME}}` → 인터뷰 1번 답변
- `{{PROJECT_DESCRIPTION}}` → 인터뷰 2번 답변 (1-2문장 설명)
- `{{PURPOSE}}` → 인터뷰 2번 답변에서 핵심 목적만 추출 (한 구절)
- `{{AUDIENCE}}` → 인터뷰 3번 답변
- `{{TECH_STACK}}` → 인터뷰 4번 답변 (없으면 "해당 없음")
- `{{LANGUAGE}}` → 인터뷰 5번 답변 (기본: 한국어)
- `{{CUSTOM_RULES}}` → `<!-- 프로젝트 진행하며 자동으로 채워집니다 -->`
- `{{DATE}}` → 오늘 날짜 (YYYY-MM-DD)

### 6. 품질 검증

WHY: 생성된 CLAUDE.md가 품질 기준을 충족해야 다음 세션에서 유용하다.

약식 검증 (6기준):
- [ ] 명령어 안내 있음 (/ci, /co)
- [ ] 파일 구조 테이블 있음
- [ ] 토큰 절약 규칙 있음
- [ ] 100줄 이하
- [ ] 프로젝트 고유 정보 포함
- [ ] 바로 실행 가능 (ci/co 가능)

### 7. 미리보기 → 확인 → 저장

생성될 5개 파일의 내용을 사용자에게 보여주고 확인을 받은 뒤 저장한다.

완료 안내: "/ci 로 첫 체크인하세요."

## 흔한 실수

| 변명 | 현실 |
|------|------|
| "나중에 세팅해도 돼" | 세팅 없이 작업하면 다음 세션에서 처음부터 다시 설명해야 함 |
| "git은 개발자만 쓰는 거야" | git은 작업 일지. 비개발자도 기록이 필요 |
| "파일이 너무 많아" | 5개 파일 각각 역할이 다름. 하나로 합치면 나중에 찾기 어려움 |
| "CLAUDE.md만 있으면 되지" | CLAUDE.md는 항상 로드됨. 모든 내용을 넣으면 토큰 낭비 |

## 위험 신호

- [ ] 인터뷰 없이 바로 파일 생성을 시도함
- [ ] 기존 CLAUDE.md를 확인 없이 덮어씀
- [ ] 100줄을 초과하는 CLAUDE.md 생성
- [ ] git init 없이 진행 (사용자가 명시적으로 거부한 경우는 제외)

## 확인 사항

- [ ] 5개 파일 모두 생성됨
- [ ] CLAUDE.md 첫 줄에 `<!-- non-dev-harness:v1 -->` 마커 있음
- [ ] CLAUDE.md 100줄 이하
- [ ] git 초기화됨 (사용자 동의한 경우)
- [ ] 사용자에게 "/ci 로 첫 체크인" 안내함
