# hs — 하네스 세팅

프로젝트 폴더에 세션 기록용 파일 5개와 git 작업 기록을 세팅합니다. /hs는 프로젝트 폴더 전용이며, 홈 폴더나 `~/.claude` 같은 넓은 폴더에는 세팅하지 않습니다.

질문은 선택지 질문 도구(AskUserQuestion)가 있으면 그것으로, 없으면 번호 목록 글로 묻습니다. 한 번에 한 주제씩 묻습니다.

## 절대 규칙

- 이미 있는 기록 파일(JOURNAL.md, MEMORY.md, ERROR.md, ISSUE.md, WIKI.md)은 어떤 모드에서도 다시 만들거나 덮어쓰지 않습니다.
- 기존 CLAUDE.md는 템플릿 구조에 맞추지 않습니다. 섹션의 순서·제목·내용은 아래 '2. 모드별 할 일'에서 정한 곳 말고는 그대로 두고, 100줄을 넘어도 기존 내용을 줄이지 않습니다.
- 미리보기를 보여 주고 사용자가 확인하기 전에는 아무것도 쓰지 않습니다. git init, `.gitignore`, 기록 파일, git 설정, 커밋이 모두 여기에 들어갑니다.
- git 사용자 정보는 `git config --local`로만 설정하고 `--global`은 쓰지 않습니다. GitHub 저장소는 `--private`로만 만들며, 공개는 사용자가 따로 요청할 때만 합니다.

## 언제 사용

- 새 프로젝트를 시작할 때 (최초 1회)
- 기존 프로젝트에 하네스를 추가할 때
- 하네스 설정을 다시 하거나 업데이트할 때

## 프로세스

### 1. 상태 판별 (읽기만)

WHY: 엉뚱한 폴더에 세팅하거나 쌓인 기록을 덮어쓰면 되돌리기 어렵다.

이 단계에서는 아무것도 쓰지 않습니다. 아래를 위에서부터 확인해 처음 맞는 모드를 정합니다. 판별한 모드와 그 모드에서 할 일을 한두 문장으로 알리고 진행할지 묻습니다(진행 / 멈춤).

**1) 하네스 찾기.** 현재 폴더부터 한 단계씩 위로 올라가며 각 폴더의 CLAUDE.md 첫 줄을 Read나 grep으로 파일에서 직접 읽습니다. 첫 줄이 `<!-- non-dev-harness:`로 시작하는 CLAUDE.md를 처음 만난 폴더가 하네스 루트입니다. 홈 폴더에 닿으면 멈추고, 홈 폴더 자체는 검사하지 않습니다. 대화에 자동으로 실린 CLAUDE.md에는 HTML 주석이 지워져 있으므로 그것으로 판단하지 않습니다.

- 상위 폴더에서 찾았으면 "상위 폴더 <경로>에 하네스가 있습니다"라고 알리고 그 폴더 기준으로 진행할지 묻습니다. 아니라고 하면 멈춥니다. 하위 폴더에 두 번째 하네스를 만들지 않습니다.
- 하네스 루트가 홈 폴더 자체, 드라이브 루트, `/Users`·`/home`·`C:\Users` 자체, `~/.claude`와 그 하위이면 진행하지 않고 멈춥니다.
- 하네스 루트가 홈 바로 아래의 바탕화면·문서·다운로드 폴더 자체이면, 개인 파일까지 함께 기록될 수 있다고 설명합니다. 옮기는 방법(새 프로젝트 폴더를 만들고, 하네스 파일과 이 프로젝트의 작업 파일을 그 안으로 옮긴 뒤, 그 폴더에서 /hs를 다시 실행)을 안내하고, 사용자가 그래도 여기서 진행하겠다고 분명히 확인했을 때만 진행합니다.
- 표식이 `<!-- non-dev-harness:v1 -->`이거나, JOURNAL.md 없이 하네스 형식 MEMORY.md(첫 줄이 `— 메모리`로 끝남)만 있으면 **업그레이드 모드**입니다.
- 그 밖에 표식이 `<!-- non-dev-harness:v2 -->`이면 **업데이트 모드**입니다.

**2) 하네스가 없을 때**

- **위험 폴더**면 멈춥니다. 홈 폴더 자체, 홈 바로 아래의 Desktop·Documents·Downloads·바탕화면·문서·다운로드, 드라이브 루트(`/`, `C:\`), `~/.claude`와 그 하위, `/Users`·`/home`·`C:\Users` 자체가 해당합니다(Git Bash에서는 `/c`, `/c/Users`로 보입니다). "이 폴더는 범위가 넓어 개인 파일까지 기록될 수 있습니다. 프로젝트용 새 폴더를 만들고 그 안에서 /hs를 다시 실행해 주세요"라고 안내합니다.
- **상위 git 저장소**: `git rev-parse --show-prefix`가 성공하고 출력이 비어 있지 않으면 현재 폴더는 더 큰 저장소의 하위 폴더입니다. `git rev-parse --show-toplevel`로 얻은 경로를 넣어 "이 폴더는 <경로>에 있는 더 큰 git 저장소의 일부입니다. 여기에 세팅하면 기록은 그 저장소 안에 남고, /co는 이 폴더 안의 변경만 저장합니다"라고 알리고 계속할지 묻습니다. 계속하면 git init은 하지 않습니다.
- **파일이 너무 많음**: `find . -maxdepth 4 -type f -not -path './.git/*' | head -n 2001 | wc -l`로 현재 폴더와 그 아래 3단계 하위 폴더까지의 파일 수를 셉니다. 2,000개를 넘으면 "파일이 2,000개가 넘습니다. 프로젝트 폴더가 맞는지 확인해 주세요"라고 경고하고 계속할지 묻습니다.
- 현재 폴더에 CLAUDE.md가 있으면 **덧붙이기 모드**, 없으면 **새로 만들기 모드**입니다.

**3) 기록 파일 하나씩 확인.** 모드와 관계없이 JOURNAL.md, MEMORY.md, ERROR.md, ISSUE.md, WIKI.md를 각각 확인합니다. 이미 있는 파일은 만들지 않습니다. 첫 줄이 하네스 제목 형식(`# <이름> — 작업 일지`, `— 메모리`, `— 에러 이력`, `— 이슈`, `— 위키`)이 아닌 같은 이름 파일은 그대로 두고, 그런 파일이 있다는 사실을 사용자에게 알립니다.

### 2. 모드별 할 일

WHY: 다시 실행할 때 필요한 부분만 고쳐야 쌓인 기록이 사라지지 않는다.

- **새로 만들기**: 템플릿으로 기록 파일 5개(CLAUDE.md, JOURNAL.md, ERROR.md, ISSUE.md, WIKI.md)를 만듭니다(이미 있는 파일은 빼고). 현재 폴더에 `AGENTS.md`가 있으면 새 CLAUDE.md의 설명 줄 아래에 `@AGENTS.md` 한 줄을 넣습니다.
- **덧붙이기**: 기존 CLAUDE.md 내용은 한 글자도 바꾸지 않습니다. 맨 앞에 표식 한 줄을 새로 넣고, 파일 끝에 템플릿의 `## 하네스 파일 안내`부터 `## 변경이력`까지를 덧붙입니다. 100줄 기준은 덧붙인 부분에만 적용하며, 기존 내용을 줄이거나 요약하지 않습니다. 다른 기록 파일은 없는 것만 만듭니다.
- **업데이트**: CLAUDE.md는 `## 프로젝트 정보` 섹션만 Edit로 고칩니다. 그 섹션이 없으면 새로 만들지 묻고, 만든다면 첫 `##` 섹션 바로 위에 넣습니다. 빠진 기록 파일만 템플릿으로 만들고, `.gitignore`에 빠진 줄이 있으면 추가를 제안합니다. 다른 섹션과 기존 기록 내용은 건드리지 않습니다.
- **업그레이드(v1에서 v2로)**: 실제 v1 프로젝트의 CLAUDE.md는 템플릿과 구성이 많이 다릅니다. 템플릿 구조를 강요하지 않고, 기존 기록 내용은 한 줄도 바꾸지 않으며, 아래만 합니다.
  - 하네스 형식 MEMORY.md(첫 줄이 `— 메모리`로 끝남)의 이름을 JOURNAL.md로 바꿉니다. 첫 줄이 그 형식이 아니면 사용자가 직접 만든 파일일 수 있으므로 바꾸지 않고 알립니다. git 저장소면 `git mv MEMORY.md JOURNAL.md`, 아니면 `mv`를 씁니다. JOURNAL.md가 이미 있으면 이름을 바꾸지 않고 알립니다. 일지가 상한(세션 로그 5개 등)을 넘었어도 이름만 바꾸고, 정리는 다음 /co 때 묻도록 둡니다.
  - 일지 첫 줄이 `— 메모리`로 끝나면 그 부분만 `— 작업 일지`로 바꿉니다.
  - CLAUDE.md 첫 줄 표식을 `<!-- non-dev-harness:v2 -->`로 바꿉니다.
  - `## 하네스 파일 안내` 표가 있으면 그 표 안의 `MEMORY.md` 낱말만 `JOURNAL.md`로 바꿉니다. 그 밖에 사용자가 쓴 `MEMORY.md` 언급(변경이력 행 등)은 목록으로 보여 주고 바꿀지 묻습니다.
  - 없는 v2 섹션(`## 기록 파일 다루는 법`, `## 원칙`)만 템플릿에서 가져와 덧붙입니다. `## 프로젝트 규칙`이 있으면 그 바로 위에, 없으면 `## 변경이력` 바로 위에, 둘 다 없으면 파일 끝에 넣습니다. 기존 섹션은 옮기지 않습니다.
  - `## 변경이력` 표가 있으면 오늘 날짜로 v2 업데이트 행을 하나 추가하고, 없으면 건너뜁니다.
  - 빠진 기록 파일(ERROR.md, ISSUE.md, WIKI.md 등)은 템플릿으로 만듭니다. 이미 있는 파일은 건드리지 않습니다.
  - `## 토큰 절약 규칙` 섹션이 있으면 아래 v1 원문과 똑같은 줄만 지우자고 제안합니다. 사용자가 고치거나 더한 줄은 남기고, 남은 줄이 없을 때만 섹션 제목도 지웁니다. 섹션이 없으면 건너뜁니다.

```
1. 큰 파일은 offset/limit으로 필요한 부분만 읽기
2. 같은 파일 중복 읽기 금지
3. git diff는 --stat 우선, 전체 diff는 필요 시만
4. 로그는 최근 3-5개만
5. 응답은 핵심만 간결하게
6. 컨텍스트 65% 도달 시 /compact 안내 (힌트 포함)
```

### 3. 인터뷰

WHY: 프로젝트 맥락을 알아야 적절한 규칙을 만들 수 있다.

- 새로 만들기: 아래 5문항을 가설-확인 방식으로 한 번에 하나씩 묻습니다. 폴더 이름과 파일에서 추론한 값을 첫 선택지로 두고, 직접 입력은 도구가 붙여 주는 기타(Other)로 받습니다. 후보가 하나뿐이면 둘째 선택지는 "다른 이름으로 할게요"처럼 직접 입력을 안내하는 항목으로 둡니다.
- 덧붙이기: 기록 파일 제목에 쓸 프로젝트 이름만 확인합니다.
- 업데이트: 지금 `## 프로젝트 정보`의 값을 보여 주고 바꿀 항목만 묻습니다. 섹션이 없고 새로 만들기로 했으면 2~5번을 묻습니다.
- 업그레이드: 인터뷰하지 않습니다.

1. **프로젝트 이름**: 폴더명에서 추론하여 제안 → 확인/수정
2. **무엇을 하는 프로젝트인가요?**: 1-2문장 (예: "블로그를 운영합니다")
3. **누구를 위한 건가요?**: 대상 (예: "개인 사용", "고객용")
4. **사용 도구**: "어떤 도구나 프로그램을 쓰시나요?" — "없음/모름"도 유효한 답변
5. **선호 언어**: 기본값 한국어

5개 항목이 채워지면 인터뷰를 끝냅니다. 파일에서 이미 알 수 있는 항목은 추론값을 확인만 받습니다.

### 4. git 준비 (묻기만 하고 실행하지 않음)

WHY: 비개발자가 git을 잊어도 작업이 안전하게 기록되어야 한다. 실행은 미리보기 확인 뒤에 한다.

- git 저장소가 아니면(`git rev-parse --is-inside-work-tree` 실패) "작업 기록(git)을 켤까요?"라고 묻습니다(켜기(추천) / 켜지 않기). 거절하면 git과 `.gitignore`, GitHub 단계를 모두 건너뜁니다.
- `.gitignore`가 없으면 아래 블록으로 새로 만들고, 있으면 블록에서 빠진 줄만 파일 끝에 블록 순서대로 덧붙입니다. 기존 줄은 지우거나 순서를 바꾸지 않습니다.
- `git config --get user.name`이나 `git config --get user.email`이 비어 있으면 기록에 남길 이름과 이메일을 사용자에게 묻습니다. 임의의 값을 지어 넣지 않습니다.

```
# non-dev-harness
.DS_Store
Thumbs.db
node_modules/
*.log
.env
.env.*
!.env.example
*.pem
*.p12
*.pfx
*.keystore
id_rsa*
id_ed25519*
id_ecdsa*
*credentials*.json
client_secret*.json
service-account*.json
token.json
secrets.*
.omc/
```

### 5. 품질 검증 → 미리보기 → 확인

WHY: 사용자가 쓰일 내용과 실행될 동작을 먼저 봐야 원치 않는 변경이 생기지 않는다.

새로 만들기와 덧붙이기 모드에서는 CLAUDE.md를 아래 기준으로 약식 검증합니다.
- [ ] 명령어 안내 있음 (/ci, /co)
- [ ] 파일 구조 테이블 있음
- [ ] `## 기록 파일 다루는 법` 있음
- [ ] `## 원칙` 있음
- [ ] 100줄 이하 (덧붙이기 모드는 덧붙인 부분만)
- [ ] 프로젝트 고유 정보 포함
- [ ] 바로 실행 가능 (ci/co 가능)

미리보기에는 만들 파일의 내용, 고칠 파일의 바뀌는 부분, 실행할 동작(git init, `.gitignore`에 넣을 줄, `git config --local`로 넣을 이름과 이메일, 이름 바꾸기, 커밋할 파일과 메시지)을 모두 보여 줍니다. 그리고 저장 / 고칠 부분 있음 / 취소 가운데 고르게 합니다. "저장"일 때만 6단계로 갑니다. 고칠 부분이 있으면 반영해 다시 보여 주고, 취소하면 아무것도 쓰지 않고 멈춥니다.

### 6. 실행

확인받은 것만 이 순서로 실행합니다.

1. git init (사용자가 동의했고 저장소가 없을 때만)
2. `.gitignore` 만들기, 또는 빠진 줄 덧붙이기
3. 기록 파일 만들기와 고치기 (아래 템플릿과 치환 규칙)
4. 이름과 이메일을 물었다면 `git config --local user.name "<이름>"`, `git config --local user.email "<이메일>"` (저장소가 있어야 하므로 git init 뒤에 합니다)
5. 커밋: 이번에 만들거나 고친 하네스 파일과 `.gitignore`만 경로를 하나씩 지정합니다. `git add -A`나 `git add .`는 쓰지 않습니다. 커밋에도 같은 경로를 지정해야 사용자가 미리 스테이징해 둔 다른 파일이 섞이지 않습니다. 업그레이드 모드는 이름을 바꾼 MEMORY.md도 경로에 넣습니다.

```
git add -- <만들거나 고친 파일들>
git commit -m "hs: 하네스 세팅" -- <같은 파일들>
```

커밋 메시지는 새로 만들기·덧붙이기 모드에서 `hs: 하네스 세팅`, 업데이트·업그레이드 모드에서 `hs: 하네스 v2 업데이트`입니다.

**템플릿.** `${CLAUDE_SKILL_DIR}/templates/`에서 템플릿을 읽어 `{{placeholder}}`를 치환합니다. 경로에 `${CLAUDE_SKILL_DIR}`가 치환되지 않은 채 보이면 이 SKILL.md와 같은 폴더의 `templates/`를 찾습니다.

- `CLAUDE.md.template` → CLAUDE.md
- `JOURNAL.md.template` → JOURNAL.md
- `ERROR.md.template` → ERROR.md
- `ISSUE.md.template` → ISSUE.md
- `WIKI.md.template` → WIKI.md

**치환 값 정리.** 사용자가 답한 값에만 적용하고, `{{CUSTOM_RULES}}`와 `{{DATE}}`처럼 정해진 값에는 적용하지 않습니다.
- 각 줄 맨 앞의 `#`과 그 뒤 공백만 지웁니다. 줄 중간의 `#`은 그대로 둡니다("C# 공부"는 바뀌지 않습니다).
- `<`로 시작해 `>`로 끝나는 태그를 지웁니다.
- 줄바꿈은 공백 하나로 바꿉니다.
- 200자를 넘으면 200자에서 자릅니다.

치환 변수:
- `{{PROJECT_NAME}}` → 인터뷰 1번 답변
- `{{PROJECT_DESCRIPTION}}` → 인터뷰 2번 답변 (1-2문장 설명)
- `{{PURPOSE}}` → 인터뷰 2번 답변에서 핵심 목적만 추출 (한 구절)
- `{{AUDIENCE}}` → 인터뷰 3번 답변
- `{{TECH_STACK}}` → 인터뷰 4번 답변 (없으면 "해당 없음")
- `{{LANGUAGE}}` → 인터뷰 5번 답변 (기본: 한국어)
- `{{CUSTOM_RULES}}` → `<!-- 프로젝트 진행하며 자동으로 채워집니다 -->`
- `{{DATE}}` → 오늘 날짜 (YYYY-MM-DD)

### 7. GitHub 연결 (선택)

WHY: 클라우드 백업은 유용하지만, 공개 저장소로 만들면 작업 폴더가 인터넷에 공개된다.

커밋이 성공했고, `gh auth status`가 성공하며(설치되어 있고 로그인됨), `git remote get-url origin`이 실패할 때(아직 원격 저장소가 없음)만 "GitHub에 비공개 저장소로 백업할까요?"라고 제안합니다(비공개로 연결 / 나중에). 저장소 이름은 영문 소문자와 하이픈으로 제안해 확인받습니다. 한글 이름은 그대로 쓰지 않습니다.

```
gh repo create <이름> --private --source=. --remote=origin --push
```

`--public`은 사용자가 공개를 따로 요청할 때만 씁니다. `gh`가 없거나 로그인되어 있지 않거나, Cowork처럼 push가 막히는 환경이면 "GitHub 백업은 나중에 내 컴퓨터의 터미널이나 Claude Code에서 언제든 할 수 있어요"라고 안내하고 건너뜁니다. 명령이 `Cowork blocked this request`로 막혀도 실패로 다루지 않고 같은 안내를 합니다.

완료 안내: "/ci 로 첫 체크인하세요."
