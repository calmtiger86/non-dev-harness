# hs — 하네스 세팅

프로젝트 폴더에 세션 기록용 파일 5개와 git 작업 기록을 세팅합니다. /hs는 프로젝트 폴더 전용이며, 홈 폴더나 `~/.claude` 같은 넓은 폴더에는 세팅하지 않습니다.

## 절대 규칙

- 미리보기 본문은 질문 도구를 부르기 **전에** 일반 글로 출력합니다. 질문 문장에도 핵심(만들·고칠 파일, 커밋 메시지)을 넣습니다. 미리보기를 실제로 출력하지 않았으면 "위 미리보기"라고 쓰지 않습니다.
- 미리보기를 보여 주고 사용자가 확인하기 전에는 아무것도 쓰지 않습니다. git init, `.gitignore`, 기록 파일, git 설정, 커밋이 모두 여기에 들어갑니다.
- 이미 있는 기록 파일(JOURNAL.md, MEMORY.md, ERROR.md, ISSUE.md, WIKI.md)은 어떤 모드에서도 다시 만들거나 덮어쓰지 않습니다.
- 기존 CLAUDE.md는 템플릿 구조에 맞추지 않습니다. 섹션의 순서·제목·내용은 모드별 references에서 정한 곳 말고는 그대로 두고, 100줄을 넘어도 기존 내용을 줄이지 않습니다.
- git 사용자 정보는 `git config --local`로만 설정하고 `--global`은 쓰지 않으며, 이름·이메일을 지어 넣지 않습니다. GitHub 저장소는 `--private`로만 만들며, 공개는 사용자가 따로 요청할 때만 합니다.

## 도구 쓰는 법

- 사용자가 고르는 질문은 모두 선택지 질문 도구(AskUserQuestion)로 묻습니다. 도구가 없을 때만 번호 목록 글로 묻습니다. 한 번에 한 주제씩 묻습니다.
- 파일 읽기는 Read·Glob·Grep 도구로만 합니다. 하네스 표식 찾기, 템플릿 읽기, 기록 파일 읽기에 Bash `head`·`cat`·`for`·`while`·변수를 쓰지 않습니다.
- Cowork처럼 Read·Glob·Grep·Edit·Write가 프로젝트 폴더에 닿지 않는 환경에서는, 그 환경에서 프로젝트 폴더를 다루는 파일 도구를 같은 원칙(파일 하나씩, 고칠 부분만)으로 씁니다. 그런 도구도 없을 때만 프로젝트 쪽 셸에서 파일 하나씩 `cat "<파일>"`로 읽습니다.
- 검사 스크립트는 본문의 한 줄을 단독으로 실행합니다. 앞뒤에 `cd`·`&&`·`;`·파이프·변수를 붙이지 않습니다.
- git 명령의 경로는 변수에 담지 않고 하나씩 따옴표로 감싸 적습니다(zsh에서는 변수에 담으면 실패합니다).
- 사용자에게 보이는 문장은 진행 안내까지 모두 한국어로 씁니다.
- "references의 X를 읽는다"는 `${CLAUDE_SKILL_DIR}/references/X`를 Read로 읽고 그대로 따른다는 뜻입니다.

## 프로세스

### 1. 상태 판별 (읽기만)

이 단계에서는 아무것도 쓰지 않습니다. 아래를 위에서부터 확인해 처음 맞는 모드를 정하고, 판별한 모드와 할 일을 한두 문장으로 알린 뒤 진행할지 묻습니다(진행 / 멈춤).

**위험 폴더 목록.** (가) 홈 폴더 자체, 드라이브 루트(`/`, `C:\`, Git Bash에서는 `/c`), `/Users`·`/home`·`C:\Users` 자체(Git Bash에서는 `/c/Users`), `~/.claude`와 그 하위. (나) 홈 바로 아래의 Desktop·Documents·Downloads·바탕화면·문서·다운로드 폴더 자체, OneDrive 폴더 자체(`~/OneDrive`, `~/OneDrive - <회사 이름>`)와 그 바로 아래의 Desktop·Documents·바탕 화면·문서 폴더.

**1) 하네스 찾기.** 현재 폴더부터 위로 올라가며 Read 도구로 각 폴더의 `CLAUDE.md`를 직접 열어(없으면 한 단계 위로, Bash `find`·`ls` 금지) 첫 줄이 `<!-- non-dev-harness:`로 시작하는 첫 폴더를 하네스 루트로 정합니다. 홈 폴더에 닿으면 멈추고 홈 자체는 검사하지 않습니다. 자동으로 실린 CLAUDE.md는 HTML 주석이 지워져 있으므로 판단에 쓰지 않습니다.

- 상위 폴더에서 찾았으면 "상위 폴더 <경로>에 하네스가 있습니다"라고 알리고 그 폴더 기준으로 진행할지 묻습니다. 아니라고 하면 멈춥니다. 하위 폴더에 두 번째 하네스를 만들지 않습니다.
- 하네스 루트가 위험 폴더 (가)에 들면 멈춥니다. (나)에 들면 개인 파일까지 기록될 수 있다고 설명하고 옮기는 방법(새 프로젝트 폴더에 하네스 파일과 작업 파일을 옮기고 그 폴더에서 /hs)을 안내한 뒤, 사용자가 그래도 진행하겠다고 분명히 고를 때만 진행합니다.
- 표식이 `<!-- non-dev-harness:v1 -->`이거나, JOURNAL.md 없이 하네스 형식 MEMORY.md(첫 줄이 `— 메모리`로 끝남)만 있으면 **업그레이드 모드**, 그 밖에 표식이 `<!-- non-dev-harness:v2 -->`이면 **업데이트 모드**입니다.

**2) 하네스가 없을 때**

- **위험 폴더**: 현재 폴더가 (가)나 (나)에 들면 멈추고, "이 폴더는 범위가 넓어 개인 파일까지 기록될 수 있습니다. 프로젝트용 새 폴더를 만들고 그 안에서 /hs를 다시 실행해 주세요"라고 안내합니다.
- **상위 git 저장소**: 현재 폴더에서 `-C` 없이 `git rev-parse --show-prefix`를 그대로 실행해 출력이 비어 있지 않으면, "이 폴더는 <`git rev-parse --show-toplevel` 경로>에 있는 더 큰 git 저장소 안에 있습니다"라고 알리고 선택지로 묻습니다: **이 폴더를 독립 기록으로 시작(git init)** / **상위 저장소에 포함**(기록은 그 저장소에 남고 /co는 이 폴더 안의 변경만 저장, git init 안 함) / **멈춤**. 상위 저장소의 최상위가 위험 폴더 (가)·(나)에 들면(바탕화면이나 홈 전체를 git으로 관리하는 경우 등) "독립 기록"을 첫 선택지(추천)로 둡니다. "독립 기록"을 고르면 references의 `independent-repo.md`를 읽고 따릅니다(두 출력 값을 기억해 두기, 상위 저장소가 이미 이 폴더 파일을 기록 중인지 안내, 상위 `.gitignore`에 넣을지 여기서 묻기만 하고 추가는 6-2에서 한 번).
- **파일이 너무 많음**: Glob 도구로 `**/*`를 한 번 찾아(Bash `find`·`wc` 금지), 결과 끝 안내 "Showing 100 of N matching files"의 N(안내가 없으면 결과 개수)이 2,000을 넘으면 경고하고 계속할지 묻습니다.
- 현재 폴더에 CLAUDE.md가 있으면 **덧붙이기 모드**, 없으면 **새로 만들기 모드**입니다.

**3) 기록 파일 하나씩 확인.** 5개 기록 파일과 MEMORY.md를 각각 확인해 이미 있는 파일은 만들지 않습니다. 첫 줄이 하네스 제목 형식(`# <이름> — 작업 일지`, `— 메모리`, `— 에러 이력`, `— 이슈`, `— 위키`)이 아닌 같은 이름 파일은 그대로 두고 알립니다.

### 2. 모드별 할 일

- **새로 만들기**: 템플릿으로 기록 파일 5개를 만듭니다(이미 있는 파일은 빼고). 3단계 인터뷰로 갑니다.
- **덧붙이기**(기존 CLAUDE.md 앞에 표식, 끝에 하네스 섹션), **업데이트**(`## 프로젝트 정보`와 빠진 파일만), **업그레이드**(MEMORY.md를 JOURNAL.md로, 표식 v2, 없는 v2 섹션만): references의 `existing-harness-modes.md`를 읽고 그 모드의 절차(인터뷰 범위, 커밋 경로 포함)를 그대로 따른 뒤 4단계로 갑니다.

### 3. 인터뷰 (새로 만들기)

아래 5문항을 한 번에 하나씩 선택지로 묻습니다. 추론한 값을 첫 선택지로 두고 직접 입력은 기타(Other)로 받습니다. 2번은 추론할 수 있어도 건너뛰지 않고 확인받습니다. 5개 항목이 채워지면 끝냅니다. 선택지 만드는 법은 references의 `interview-guide.md`를 읽습니다.

1. **프로젝트 이름**: 폴더명에서 추론하여 제안 → 확인/수정
2. **무엇을 하는 프로젝트인가요?**: 1-2문장 (예: "블로그를 운영합니다")
3. **누구를 위한 건가요?**: 대상 (예: "개인 사용", "고객용")
4. **사용 도구**: "어떤 도구나 프로그램을 쓰시나요?" — "없음/모름"도 유효한 답변
5. **선호 언어**: 기본값 한국어

### 4. git 준비 (묻기만 하고 실행하지 않음)

- 1단계에서 "독립 기록"을 골랐으면 git을 켜는 것으로 보고 6-1에서 이 폴더에 git init을 합니다. 그 밖에 git 저장소가 아니면(현재 폴더에서 `-C` 없이 `git rev-parse --is-inside-work-tree` 실패) "작업 기록(git)을 켤까요?"라고 묻습니다(켜기(추천) / 켜지 않기). 거절하면 git과 `.gitignore`, GitHub 단계를 모두 건너뜁니다.
- `.gitignore`가 없으면 아래 블록으로 새로 만들고, 있으면 블록에서 빠진 줄만 파일 끝에 블록 순서대로 덧붙입니다. 기존 줄은 지우거나 순서를 바꾸지 않습니다(업그레이드의 v1 줄 질문은 예외).

### 5. 품질 검증 → 미리보기 → 확인

새로 만들기·덧붙이기에서는 CLAUDE.md(덧붙이기는 덧붙인 부분)에 /ci·/co 안내, 파일 표, `## 기록 파일 다루는 법`, `## 원칙`, 프로젝트 고유 정보가 있고 100줄 이하인지 확인합니다.

미리보기 본문을 먼저 일반 글로 출력합니다.
- 만들 파일: 파일마다 이름과 내용(CLAUDE.md는 전문, 나머지는 첫 줄과 섹션 제목)
- 고칠 파일: 바뀌는 줄의 전과 후
- 실행할 동작: git init 여부, `.gitignore`에 넣을 줄, 상위 저장소 `.gitignore`(경로)에 넣을 줄(독립 기록일 때), `git config --local`로 넣을 이름과 이메일, 이름 바꾸기, 커밋할 파일 목록, 커밋 메시지

그다음 질문 도구로 저장 / 고칠 부분 있음 / 취소 가운데 고르게 합니다. 질문 문장에 핵심을 넣습니다(예: "CLAUDE.md 등 파일 6개를 만들고 git을 켠 뒤 'hs: 하네스 세팅'으로 커밋할까요?"). "저장"일 때만 6단계로 갑니다. 고칠 부분이 있으면 반영해 다시 보여 주고, 취소하면 아무것도 쓰지 않고 멈춥니다.

### 6. 실행

확인받은 것만 이 순서로 실행합니다. 쓰기 명령(add, config --local, mv, reset)은 **현재 폴더가 하네스 루트일 때** `-C` 없이 본문 모양 그대로 실행합니다. 그중 add, reset, 사용자 정보 설정은 사전 승인되어 확인 창 없이 지나가고, mv(파일 이름 변경)는 확인 창이 뜹니다. 커밋은 6-6의 검사·커밋 스크립트로만 하며, 이 스크립트도 사전 승인되어 있습니다. 현재 폴더가 하네스 루트가 아니면(상위 폴더 하네스) 같은 명령에 `-C "<하네스 루트>"`를 붙여 `git -C "<하네스 루트>" …`로 실행하고, 이때는 확인 창이 뜹니다. `git`과 하위 명령 사이에 `-c` 같은 다른 옵션을 넣지 않습니다. git init은 6-1의 모양으로 실행하며 확인 창이 뜹니다. 읽기 명령(rev-parse, config --get, remote get-url, ls-files)은 사전 승인이 맞도록 현재 폴더에서 `-C` 없이 본문의 모양 그대로 실행하고, 현재 폴더가 하네스 루트가 아닐 때(상위 폴더 하네스)만 `-C`를 붙입니다. 파일을 쓰기 직전에 "파일 N개를 만들 때마다 확인 창이 뜨고, 창에 파일 내용이 보입니다"라고 한 줄 알립니다(창을 줄이려고 Bash 한 덩어리로 쓰지 않습니다).

6-1. git init (동의했고 저장소가 없을 때, 또는 1단계에서 "독립 기록"을 골랐을 때만): `git init "<하네스 루트>"`. "독립 기록"이면 바로 뒤에 현재 폴더에서 `-C` 없이 `git rev-parse --show-prefix`를 그대로 실행해 출력이 빈 줄인지 확인합니다(현재 폴더가 하네스 루트가 아닐 때만 `git -C "<하네스 루트>" rev-parse --show-toplevel`이 하네스 루트와 같은지로 확인). 확인이 맞지 않거나 init이 실패·거절되면 6-2 이후(스테이징·커밋 포함)를 하지 않고 "이 폴더만의 기록을 시작하지 못했습니다. 상위 저장소에는 아무것도 기록하지 않았습니다"라고 알린 뒤 멈춥니다. 맞으면 4단계에서 미룬 사용자 정보를 여기서 확인합니다.
6-2. `.gitignore` 만들기, 또는 빠진 줄 덧붙이기. "독립 기록"에서 상위 저장소 `.gitignore`에 넣기로 했으면 여기서 한 번만, `independent-repo.md`의 줄 모양(`/`로 시작하고 `/`로 끝나는 고정 경로, 특수 글자는 `\`로 막기)대로 <상위 최상위>의 `.gitignore`에 추가합니다.
6-3. 기록 파일 만들기와 고치기 (아래 템플릿과 치환 규칙). 새 파일은 Write 도구로, 있는 파일은 Edit 도구로 하나씩 씁니다.
6-4. 이름과 이메일을 물었다면 `git config --local user.name "<이름>"`, `git config --local user.email "<이메일>"`
6-5. 스테이징: 이번에 만들거나 고친 하네스 파일과 `.gitignore`만 경로를 하나씩 적습니다. `git add -A`나 `git add .`는 쓰지 않습니다. 이름을 바꾼 MEMORY.md는 넣지 않습니다.
   `git add -- "CLAUDE.md" "JOURNAL.md" "ERROR.md" "ISSUE.md" "WIKI.md" ".gitignore"` (실제로 만들거나 고친 파일만)
6-6. 검사와 커밋: 사용자가 쓴 기존 내용이 처음 기록될 수 있으므로 비밀 파일 검사를 통과했을 때만 커밋합니다. 아래 한 줄만 단독으로 실행합니다. `--` 뒤에는 6-5에서 스테이징한 경로를 그대로 적습니다(업그레이드는 references의 경로 규칙대로). 스크립트는 HEAD에 그 경로의 작업 파일만 더한 내용을 고정해 검사하고, 통과하면 검사한 그대로 커밋합니다(git 훅은 실행하지 않습니다). `git commit`을 따로 실행하지 않습니다. 현재 폴더가 하네스 루트 안이어야 하고, 6-3에서 만든 CLAUDE.md 첫 줄의 표식으로 하네스 루트를 확인합니다.

```bash
bash "${CLAUDE_SKILL_DIR}/../co/scripts/commit-checked.sh" "<하네스 루트>" "hs: 하네스 세팅" -- "CLAUDE.md" "JOURNAL.md" …
```

   - 종료 코드가 0이고 마지막 줄이 `[커밋] <해시> <제목>`이면 커밋된 것입니다. 스크립트는 지정한 경로의 작업 파일 내용만 따로 검사해 커밋하므로, 사용자가 미리 스테이징해 둔 다른 파일은 이번 커밋에 들어가지 않고 스테이징에 그대로 남습니다.
   - 종료 코드 4(걸림, 6-5에서 스테이징한 파일이 `:(top)경로`로 나옴): 6-5의 파일을 `git reset -q -- "CLAUDE.md" …`로 되돌리고 커밋하지 않은 채 멈춥니다. 이유를 쉬운 말로 설명합니다(비밀 값 자체는 출력하지 않음). 사용자가 비밀이 아니라고 분명히 말하면 다시 스테이징하고, 같은 줄에서 스크립트 이름만 `commit-allowed.sh`로 바꾸고 `--` 앞에 `--allow "<걸린 경로>"`를 붙여 다시 실행합니다. 이 명령에는 확인 창이 뜨니, 창에 뜨는 `--allow` 뒤 경로가 그 파일이 맞는지 보고 허락해 달라고 먼저 한 줄 알립니다(`commit-checked.sh`는 `--allow`를 거부합니다). 업그레이드에서 JOURNAL.md가 걸리면 `existing-harness-modes.md`의 안내를 따릅니다.
   - 종료 코드 3(검사가 끝까지 돌지 않음, 또는 지정한 경로를 담지 못함)이나 5(커밋 실패. 분리된 HEAD나 진행 중인 병합도 여기에 듦): 6-5의 파일을 되돌리고 커밋하지 않은 채 오류 문장을 보여 줍니다. 다시 시도하지 않고, 기록 파일은 그대로 두었으니 /co를 하면 다시 검사해 기록한다고 안내합니다.
   - 종료 코드 2: 메시지 오류면 고쳐서 한 번만 다시 실행합니다. 루트 오류("하네스 루트가 아닙니다", "현재 폴더가 하네스 루트 안이 아닙니다")면 다시 시도하지 않고 6-5의 파일을 되돌린 뒤 이유를 알리고, /co로 기록하라고 안내합니다.
   - 셸이 이 스크립트 파일을 찾지 못하거나 열지 못했다는 오류(`…/commit-checked.sh: No such file or directory` 또는 `…/commit-checked.sh: Permission denied`)만 나왔으면 스테이징을 되돌리지 않은 채 `${CLAUDE_SKILL_DIR}/../co/references/run-script-elsewhere.md`를 Read로 읽고 그 절차로 옮겨 실행합니다(Cowork에서 생김). 결과는 이 단계의 규칙대로 읽고, 그 절차가 멈추면 종료 코드 3과 같이 처리합니다.
   - bash 없음(셸이 `bash` 명령 자체를 찾지 못했다는 오류와 종료 코드 127이 함께 나올 때만): 직접 판단하지 않고 커밋을 /co로 넘깁니다.
   - 되돌리기 권한 창을 거절하면 그 파일이 아직 커밋 목록에 있으니 다른 도구로 커밋하지 말라고 알립니다.
6-7. 커밋 메시지: 새로 만들기·덧붙이기 모드에서 `hs: 하네스 세팅`, 업데이트·업그레이드 모드에서 `hs: 하네스 v2 업데이트`입니다. 메시지 인자에는 줄바꿈을 넣지 않습니다(확인 창이 뜹니다). 환경이 붙이라고 안내하는 `Co-Authored-By:` 줄은 메시지 바로 뒤, `--` 앞에 `--trailer "<그 줄 그대로>"`로 넘깁니다. `Claude-Session:` 줄은 넣지 않습니다(넣으면 스크립트가 거부합니다).

Cowork 파일 삭제 허용 창, `index.lock` 오류, 커밋 실패는 `${CLAUDE_SKILL_DIR}/../co/references/git-troubleshooting.md`를 Read로 읽고 따릅니다.

**템플릿.** 템플릿(`${CLAUDE_SKILL_DIR}/templates/`)으로 파일을 만들 때는 references의 `templates.md`를 읽고 따릅니다. 템플릿 이름(`CLAUDE.md.template`, `JOURNAL.md.template`, `ERROR.md.template`, `ISSUE.md.template`, `WIKI.md.template`)은 정해져 있으므로 목록을 보지 않고 Read 도구로 바로 엽니다. 목록이 꼭 필요하면 Glob 도구로 봅니다(Bash `ls`·`cat` 금지).

### 7. GitHub 연결 (선택)

6-7 커밋이 성공했으면 references의 `github-connect.md`를 읽고, 거기 적힌 조건(하네스 루트가 저장소 최상위, `gh auth status` 성공, `git remote get-url origin` **실패** = 원격이 **없을 때만**. 확인 명령은 현재 폴더에서 `-C` 없이 그 모양 그대로)이 모두 맞을 때만 선택지 질문으로 비공개 저장소 연결을 제안합니다. `gh`가 없거나 Cowork에서 막히면 실패로 다루지 않고 "나중에 할 수 있어요"라고 안내하고 건너뜁니다.

완료 안내: "/ci 로 첫 체크인하세요." 독립 기록에서 상위 `.gitignore`를 고쳤으면 "상위 저장소의 `.gitignore` 변경은 커밋하지 않았습니다. 상위 저장소에서 따로 기록해 주세요"를 한 줄 붙입니다.
