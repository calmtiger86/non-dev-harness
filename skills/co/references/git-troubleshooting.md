이 파일은 /co나 /hs의 git 단계에서 문제가 생겼을 때 읽습니다: Cowork의 파일 삭제 허용 확인 창, `index.lock` 오류, 커밋 실패, push 실패·거절·Cowork 차단, 읽기 명령의 "outside repository" 오류.

# git 문제 해결

## 읽기 명령이 "outside repository"로 실패할 때
현재 폴더가 하네스 루트와 다른 저장소입니다(루트 안에 내려받은 다른 프로젝트 등). 목록·설정·원격을 보는 읽기 명령도 `git -C "<루트>"`로 다시 실행합니다.

## Cowork의 "파일 영구 삭제 허용" 확인 창
- Cowork에서 스테이징이나 커밋을 할 때 "이 폴더 안의 파일을 영구 삭제하도록 허용할까요?" 같은 확인 창이 뜰 수 있습니다.
- git이 기록을 저장하면서 이 프로젝트 폴더 안(`.git` 폴더)에 잠깐 만든 잠금 파일을 지우려는 것이고, 작업 파일을 지우는 것이 아니라고 쉬운 말로 설명합니다.
- 사용자가 허용하지 않으면 커밋을 건너뜁니다. /co는 "기록 파일은 이 폴더에 저장되었습니다. git 기록은 내 컴퓨터의 터미널이나 Claude Code에서 /co를 다시 하면 남습니다"라고 안내한 뒤 '7. 체크아웃 요약'으로 갑니다. /hs는 만든 기록 파일은 그대로 둔 채 "git 기록은 내 컴퓨터의 터미널이나 Claude Code에서 /co를 하면 함께 남습니다"라고 안내하고, 7단계 GitHub 연결도 건너뜁니다.

## `index.lock` 오류
git이 `index.lock`이 이미 있다고 실패하면(Cowork에서 삭제 허용을 거절한 뒤 포함), 다른 터미널이나 앱에서 git 작업이 돌고 있지 않은지 사용자에게 확인합니다. 돌고 있지 않다고 하면 허락을 받아 그 파일 하나(`<저장소>/.git/index.lock`)만 지우고 다시 진행합니다. 다른 파일은 지우지 않습니다.

## 커밋이 실패할 때
작성자 정보 없음, 쓰기 권한 없음 등으로 커밋 자체가 실패하면 이미 저장한 기록 파일은 그대로 두고, "기록 파일은 이 폴더에 저장되었습니다. git 기록은 내 컴퓨터의 터미널이나 Claude Code에서 /co를 다시 하면 남습니다"라고 안내하고 '7. 체크아웃 요약'으로 갑니다. 작성자 정보는 사용자에게 물어 `git config --local`로만 설정합니다(현재 폴더가 하네스 루트가 아니면 `git -C "<루트>" config --local`).

## push가 실패할 때
- `Cowork blocked this request`로 막히면 실패로 다루지 않습니다. "기록은 이 폴더에 저장되었고, 클라우드 백업은 내 컴퓨터의 터미널이나 Claude Code에서 /co를 다시 하면 올라갑니다"라고 안내하고 끝냅니다.
- 거절되면 강제 push(`--force`, `--force-with-lease`)를 하지 않고, pull·merge·rebase도 스스로 하지 않습니다. "다른 컴퓨터나 GitHub 웹에서 먼저 올린 기록이 있을 수 있습니다. 이 컴퓨터의 커밋은 안전하게 남아 있습니다"라고 설명하고 멈춥니다.
- 로그인 만료나 큰 파일처럼 다른 이유로 실패해도 원인을 설명하고 멈춥니다.
