이 파일은 /co 2단계에서 분류나 포함·제외 기준이 애매할 때, 그리고 4단계에서 기록 파일이 상한을 넘었을 때 읽습니다.

# 체크아웃 분류 규칙 (상세)

일지 파일은 JOURNAL.md입니다. 옛 형식(v1) 프로젝트에서 JOURNAL.md가 없고 MEMORY.md가 있으면 MEMORY.md를 일지로 씁니다.

## 6가지 분류 유형

### 1. 규칙 → CLAUDE.md
- 이 프로젝트에서 항상 적용되는 관례
- 예: "이 프로젝트에서는 항상 한국어로 작성", "파일명은 kebab-case"
- 반드시 1줄로 압축
- 일반 상식이나 일시적인 것은 제외
- "변경이력" 표에는 규칙이나 하네스 구조가 바뀐 날에만 행을 추가 (최근 10행 유지)

### 2. 의사결정 → JOURNAL.md
- A 대신 B를 선택한 이유
- 고려한 대안과 기각 사유
- 예: "블로그 플랫폼으로 X 선택. Y는 비용 때문에 기각"

### 3. 세션 요약 + 다음 할 일 → JOURNAL.md
- 오늘 한 일 (1-2문장)
- 다음에 할 일 (구체적, `- 다음 할 일:` 아래 하위 목록)
- "마지막 세션" 섹션은 다음 `##` 전까지 본문을 바꿈
- 지난 "다음 할 일" 중 끝내지 못한 항목은 새 목록에 이어 적거나 ISSUE.md로 옮김. 지우려면 먼저 사용자에게 물음
- "세션 로그" 맨 아래에 `- YYYY-MM-DD — 한 줄 요약` 추가

### 4. 에러 → ERROR.md
- 유형 태그 필수: `[환경]` `[코드]` `[연동]` `[데이터]` `[권한]`
- 시도한 복구 방법 기록
- 해결됨 → 미해결에서 해결됨으로 이동
- 패턴 발견 시 → WIKI.md "교훈"으로 승급 제안

### 5. 이슈 → ISSUE.md
- 우선순위 부여: 🔴 높음 · 🟡 중간 · 🟢 낮음
- 해결됨 → 미해결에서 해결됨으로 이동

### 6. 영구 지식 → WIKI.md
- 프로젝트 고유 학습
- 외부에서 찾기 어려운 정보
- 적절한 카테고리 선택: 일반/기술/워크플로우/교훈
- 항목을 넣을 때 "목차"에 `- [섹션] 제목` 한 줄을 함께 추가

## 포함/제외 기준

### 포함
- 프로젝트 고유한 것 (다른 프로젝트에서는 다를 수 있는 것)
- 재현 불가능한 학습 (시행착오로 알게 된 것)
- 환경 특이사항 (특정 설정이 필요한 이유)
- 향후 세션에 도움이 되는 것

### 제외
- 일반 상식 (검색하면 나오는 것)
- 1회성 에러 (재발 가능성 없음)
- 코드에서 바로 읽히는 것 (변수명이 설명하는 것)
- 이번 세션에서만 의미 있는 임시 정보

## 상한을 넘었을 때

넘은 것만 하나씩 옮길지 묻습니다(선택지 질문 도구로).
- JOURNAL.md 세션 로그 5개 초과 → "오래된 로그를 WIKI.md '세션 아카이브'로 옮길까요?"
- ERROR.md 미해결 10개 초과 → "오래된 에러를 WIKI.md '교훈'으로 정리할까요?"
- ERROR.md 해결됨 20개 초과 → 오래된 해결 기록을 WIKI.md '교훈'으로 아카이브 제안
- ISSUE.md 미해결 15개 초과 → "낮은 우선순위 이슈를 WIKI.md로 옮길까요?"
- ISSUE.md 해결됨 30개 초과 → 오래된 해결 기록을 WIKI.md '세션 아카이브'로 아카이브 제안
- CLAUDE.md 변경이력 10행 초과 → "오래된 변경이력을 WIKI.md '세션 아카이브'로 옮길까요?" (최근 10행 유지)
- CLAUDE.md 100줄 초과 → "규칙이 많아졌어요. WIKI.md로 옮길 항목 있을까요?"
- 옮길 때는 WIKI.md "목차"에도 `- [섹션] 제목` 한 줄을 함께 추가합니다.
