이 파일은 /co 6-4 검사에서 파일이 걸렸거나, 검사가 실패했을 때(`[끝]` 없음, 종료 코드가 0이 아님), bash가 없어 검사를 실행하지 못했을 때 읽습니다. 걸렸거나 실패했으면 스테이징은 SKILL.md 지시대로 이미 되돌린 상태여야 하고, bash가 없을 때는 스테이징을 유지한 상태입니다.

# 검사에 걸렸거나 검사가 실패했을 때

## 검사 출력 읽는 법
- 스크립트는 스테이징된 모든 파일(커밋에 들어갈 전부)을 검사합니다. `[이름]`, `[내용]`, `[크기]` 머리말 아래에 걸린 파일이 `:(top)경로` 모양으로 나오고, 비밀 값 자체는 나오지 않습니다.
- 이 경로는 아래 git 명령에 따옴표로 감싸 그대로 씁니다. 사용자에게 보여 줄 때는 `:(top)`을 떼고 보여 줍니다.
- 한계: git이 바이너리로 보는 파일(UTF-16 텍스트, Office 문서 등)은 내용 검사를 하지 못합니다.
- 이 파일의 `${CLAUDE_SKILL_DIR}`는 치환되지 않습니다. SKILL.md 6-4 검사 명령에 실제로 적힌 스킬 폴더 경로로 바꿔 씁니다(bash 변수로 남기면 빈 값이 됩니다).

## 검사가 실패했을 때 (종료 코드가 0이 아니거나 `[끝]`이 없음)
- 직접 판단으로 대신하지 않습니다. 스테이징은 되돌린 채 커밋하지 않고 멈춥니다.
- 스크립트가 낸 오류 문장(예: "검사 실패: 변경 내용을 읽지 못했습니다")을 그대로 보여 주고, git 기록은 이번에 남기지 않았으며 기록 파일은 저장되어 있다고 알립니다. 다음 /co에서 다시 시도하자고 안내합니다.

## bash가 없을 때만 (직접 확인)
- 셸이 `bash` 명령 자체를 찾지 못했다는 오류(예: `command not found: bash`)와 종료 코드 127이 함께 나온 경우에만 이 절을 따릅니다. 스크립트 파일을 찾지 못한 오류(`bash: …/check-staged.sh: No such file or directory`, 이것도 종료 코드 127)나 그 밖의 실패는 위 "검사가 실패했을 때"를 따릅니다. 스테이징은 되돌리지 않은 상태로 둡니다(되돌리면 확인할 목록이 비어 버립니다).
- `scripts/check-staged.sh`를 Read로 열어 기준(이름 패턴, 내용 패턴, 50MB)을 확인합니다. 그다음 현재 폴더에서 `-C` 없이 아래 명령으로 **스테이징된 내용**(커밋에 그대로 들어갈 것)을 보고 같은 기준으로 판단합니다. 작업 폴더의 파일을 Read나 Grep으로 보지 않습니다. 일부만 스테이징된 파일은 작업 폴더의 내용과 커밋될 내용이 다르기 때문입니다.
  - 목록: `git -c diff.relative=false -c core.quotePath=false diff --cached --name-only --no-renames --diff-filter=d`
  - 추가된 줄: `git -c diff.relative=false diff --cached -U0 --no-color --no-ext-diff --no-textconv --no-renames --diff-filter=d` (`+`로 시작하는 줄만 봅니다)
  - 크기: 위 출력에서 `Binary files`로 나온 파일만 `git cat-file -s ":<경로>"`로 바이트 수를 봅니다.
- 위 명령 가운데 하나라도 실패했거나 출력이 너무 길어 끝까지 보지 못했다면 직접 확인을 할 수 없는 경우로 봅니다.
- 걸린 것이 있으면 그때 `git -C "<루트>" reset -q -- "<루트>"`로 스테이징을 되돌리고 커밋하지 않은 채 아래 "걸린 파일 다루기"를 따릅니다.
- 걸린 것이 없으면 SKILL.md의 6-5 커밋으로 갑니다. 직접 확인도 할 수 없으면 스테이징을 되돌리고 멈춘 뒤 이유를 설명합니다.

## 걸린 파일 다루기
- 커밋하지 않고 멈춘 상태에서, 어떤 파일이 왜 걸렸는지 쉬운 말로 설명합니다. 걸린 파일이 여럿이면 **파일마다 질문을 따로** 합니다(한 질문에 여러 파일을 묶지 않음). 파일 하나의 선택지는 ".gitignore에 넣고 이번 기록에서 빼기" / "비밀이 아니니 그대로 기록(`--allow`)" / "이번엔 아무것도 기록하지 않기"입니다. 걸린 파일이 루트 밖에 있으면 그 파일도 `git -C "<루트>" reset -q -- "<걸린 경로>"`로 내립니다.
- 아직 기록된 적 없는 파일(현재 폴더에서 `-C` 없이 `git ls-files -- "<걸린 경로>"`를 실행한 결과가 비어 있음)이면 `.gitignore`에 그 파일이나 패턴을 추가하자고 제안합니다.
- 이미 기록 중인 파일이면 `.gitignore`에 넣는 것만으로는 계속 올라간다고 설명하고, `.gitignore`에 넣는 것과 `git -C "<루트>" rm --cached -- "<걸린 경로>"`로 기록에서 빼는 것을 함께 하도록 안내합니다(컴퓨터의 파일은 지워지지 않습니다). `.gitignore` 없이 `git rm --cached`만 하면 다음 스테이징 때 다시 올라갑니다.
- 비밀 키가 걸렸다면, 예전 기록에 이미 들어간 키는 남아 있으므로 키를 새로 발급받도록 권합니다.
- 50MB가 넘는 파일은 기록을 무겁게 만들고 100MB부터는 GitHub가 받지 않는다고 설명하고 `.gitignore` 추가를 제안합니다.
- 걸린 파일이 비밀이 아니라고 사용자가 분명히 말하면, 6-3부터 다시 하되 검사에 `--allow "<걸린 경로>"`를 붙여 그 파일을 뺍니다. 명령은 한 줄 단독으로 실행합니다: `bash "${CLAUDE_SKILL_DIR}/scripts/check-staged.sh" "<루트>" --allow "<걸린 경로>"`. 뺀 파일 말고 걸린 것이 없으면 통과입니다. 예외는 그 실행에만 적용됩니다.
- 사용자가 정리를 마치면 6-3부터 다시 합니다. `.gitignore`를 고쳤다면 그 변경도 이번 커밋에 함께 들어간다고 알립니다.
- 걸린 비밀 값 자체는 대화에 출력하지 않습니다.
- 스테이징 되돌리기(`git reset`) 권한 창을 사용자가 거절했다면, 걸린 파일이 아직 커밋 목록에 올라가 있으니 다른 도구로 커밋하지 말라고 알립니다.

## 왜 /hs의 `.gitignore`에 없는 이름이 걸리나
- `.envrc`, `.npmrc`, `.netrc`, `*.ppk`, `id_dsa*`는 이 검사의 이름 목록에는 있지만 /hs가 만드는 `.gitignore` 블록에는 일부러 넣지 않았습니다. `.npmrc`처럼 비밀 없이 기록하는 경우도 많아서, 처음부터 빼 버리지 않고 걸렸을 때 사용자가 내용을 보고 `.gitignore`에 넣을지 `--allow`로 넘길지 고르게 한 것입니다(`.npmrc` 안의 `npm_` 토큰은 내용 검사가 따로 잡습니다).
