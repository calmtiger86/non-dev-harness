이 파일은 SKILL.md의 실행 줄(`bash "<스크립트 경로>" "<루트>" …`)을 먼저 그대로 실행했는데 셸이 스크립트 파일을 찾지 못했을 때(`<스크립트 경로>: No such file or directory`)만 읽습니다. Cowork처럼 플러그인 파일과 프로젝트 폴더가 서로 다른 곳(예: 클라우드 작업 공간과 컴퓨터 쪽 가상 머신)에 있으면 생깁니다. 실행 줄을 먼저 실행해 보지 않고 이 절차로 오지 않습니다.

# 스크립트를 프로젝트 쪽으로 옮겨 실행하기

## 지키는 것
- 옮긴 파일이 원본과 바이트까지 같다는 것을 해시로 확인한 뒤에만 실행합니다.
- 스크립트 내용을 고치거나 줄이지 않습니다. 스크립트 없이 git 명령을 직접 조합해 검사를 대신하지 않습니다.
- 확인이 안 되면 SKILL.md의 "스크립트 실패"로 처리합니다. /co와 /hs는 스테이징을 되돌리고 커밋하지 않은 채 멈추고, /ci는 SKILL.md에 적힌 대체 확인으로 갑니다.
- 아래 `<스크립트 경로>`는 SKILL.md 실행 줄에 적힌 실제 경로입니다. 이 파일 안의 `${CLAUDE_SKILL_DIR}`는 치환되지 않으므로 그 표기를 명령에 쓰지 않습니다. `<이름>`은 그 경로의 파일 이름(`check-staged.sh`, `status.sh`)입니다.

## 순서
1. **기대 해시.** 스크립트를 읽을 수 있는 쪽(파일 도구, 또는 그 파일이 보이는 셸)에서 `<스크립트 경로>`와 같은 폴더의 `SHA256SUMS`를 읽고, `<이름>` 줄의 앞 64글자를 기대 해시로 씁니다. 파일이나 그 줄이 없으면 멈춥니다.
2. **인코딩.** 스크립트 파일이 보이는 셸에서 `gzip -c "<스크립트 경로>" | base64`를 단독으로 실행합니다.
3. **옮기기.** 프로젝트 폴더가 보이는 셸에서 아래 한 줄을 실행합니다. `<인코딩 값>`에는 2단계 출력을 한 글자도 바꾸지 않고 그대로 넣습니다(줄바꿈 포함).

   ```bash
   mkdir -p "$HOME/non-dev-harness-scripts" && printf '%s\n' '<인코딩 값>' | base64 -d | gunzip > "$HOME/non-dev-harness-scripts/<이름>"
   ```

   `base64 -d`가 지원되지 않는다는 오류면 `base64 -D`로 바꿉니다. 스크립트 파일이 보이는 셸이 없고 파일 도구로만 읽히면 2단계 대신, 읽은 내용을 줄 번호 표시만 빼고 그대로 따옴표 친 heredoc으로 씁니다.

   ```bash
   mkdir -p "$HOME/non-dev-harness-scripts" && cat > "$HOME/non-dev-harness-scripts/<이름>" <<'NDH_SCRIPT_EOF'
   (스크립트 내용 그대로)
   NDH_SCRIPT_EOF
   ```

4. **확인.** 프로젝트 쪽 셸에서 `sha256sum "$HOME/non-dev-harness-scripts/<이름>"`(명령이 없으면 `shasum -a 256 "$HOME/non-dev-harness-scripts/<이름>"`)를 실행하고, 앞 64글자가 1단계의 기대 해시와 같은지 봅니다. 다르면 2~3단계를 한 번만 다시 합니다. 그래도 다르면 멈춥니다.
5. **실행.** SKILL.md의 실행 줄에서 스크립트 경로만 `$HOME/non-dev-harness-scripts/<이름>`으로 바꿔 실행합니다(`"<루트>"`, `--allow` 같은 나머지 인자는 그대로). 결과는 SKILL.md의 규칙대로 읽습니다.

## 덧붙임
- `$HOME/non-dev-harness-scripts/`는 프로젝트 폴더 밖이라 커밋에 들어가지 않습니다. 같은 세션에서 다시 쓸 때도 4단계의 해시 확인을 다시 거칩니다. 확인하지 않은 파일을 실행하지 않습니다.
- 사용자에게는 "검사 도구를 이 폴더 쪽으로 옮겨, 원본과 같은지 확인한 뒤 실행했습니다" 정도로 한 줄만 알립니다.
