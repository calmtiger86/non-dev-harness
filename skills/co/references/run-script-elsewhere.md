이 파일은 SKILL.md의 실행 줄(`bash "<스크립트 경로>" "<루트>" …`)을 먼저 그대로 실행했는데 셸이 스크립트 파일을 찾지 못했거나 열지 못했을 때(`<스크립트 경로>: No such file or directory`, 종료 코드 127, 또는 `<스크립트 경로>: Permission denied`, 종료 코드 126)만 읽습니다. Cowork처럼 플러그인 파일과 프로젝트 폴더가 서로 다른 곳(예: 클라우드 작업 공간과 컴퓨터 쪽 가상 머신)에 있으면 생깁니다. 실행 줄을 먼저 실행해 보지 않고 이 절차로 오지 않습니다.

# 스크립트를 프로젝트 쪽으로 옮겨 실행하기

## 지키는 것
- 옮긴 파일이 원본과 바이트까지 같다는 것을 해시로 확인한 뒤에만 실행합니다.
- 스크립트 내용을 고치거나 줄이지 않습니다. 스크립트 없이 git 명령을 직접 조합해 검사를 대신하지 않습니다.
- 확인이 안 되면 SKILL.md의 "스크립트 실패"로 처리합니다. /co와 /hs는 스테이징을 되돌리고 커밋하지 않은 채 멈추고, /ci는 SKILL.md에 적힌 대체 확인으로 갑니다.
- 아래 `<스크립트 경로>`는 SKILL.md 실행 줄에 적힌 실제 경로입니다. 이 파일 안의 `${CLAUDE_SKILL_DIR}`는 치환되지 않으므로 그 표기를 명령에 쓰지 않습니다. `<이름>`은 그 경로의 파일 이름(`commit-checked.sh`, `status.sh`)입니다.
- 실행 줄의 스크립트가 `commit-checked.sh`이면 같은 폴더의 `check-staged.sh`도 함께 옮깁니다(`commit-checked.sh`가 자기 폴더의 `check-staged.sh`를 부릅니다). `commit-allowed.sh`이면 `commit-checked.sh`와 `check-staged.sh`까지 세 파일을 옮깁니다. 옮긴 파일 모두 1~4단계를 거칩니다.

## 순서
1. **기대 해시.** 스크립트를 읽을 수 있는 쪽(파일 도구, 또는 그 파일이 보이는 셸)에서 `<스크립트 경로>`와 같은 폴더의 `SHA256SUMS`를 읽고, 옮길 파일마다 그 이름 줄의 앞 64글자를 기대 해시로 씁니다. 파일이나 그 줄이 없으면 멈춥니다.
2. **새 임시 폴더.** 프로젝트 폴더가 보이는 셸에서 `mktemp -d "${TMPDIR:-/tmp}/ndh-script.XXXXXX"`를 단독으로 실행하고, 출력된 경로를 `<폴더>`로 그대로 씁니다. 실행할 때마다 새로 만들고, 다른 실행이나 지난 실행의 폴더를 다시 쓰지 않습니다(그 사이에 다른 실행이 파일을 바꿀 수 있기 때문). 이 폴더는 프로젝트 폴더 밖이라 커밋에 들어가지 않습니다.
3. **옮기기.** 파일마다 다음을 합니다.
   - 스크립트 파일이 보이는 셸에서 `gzip -c "<스크립트 폴더>/<이름>" | base64`를 단독으로 실행합니다.
   - 프로젝트 폴더가 보이는 셸에서 아래 한 줄을 실행합니다. `<인코딩 값>`에는 바로 앞 출력을 한 글자도 바꾸지 않고 그대로 넣습니다(줄바꿈 포함). `base64 -d`가 지원되지 않는다는 오류면 `base64 -D`로 바꿉니다.

   ```bash
   printf '%s\n' '<인코딩 값>' | base64 -d | gunzip > "<폴더>/<이름>"
   ```

   - 스크립트 파일이 보이는 셸이 없고 파일 도구로만 읽히면, 읽은 내용을 줄 번호 표시만 빼고 그대로 따옴표 친 heredoc으로 씁니다.

   ```bash
   cat > "<폴더>/<이름>" <<'NDH_SCRIPT_EOF'
   (스크립트 내용 그대로)
   NDH_SCRIPT_EOF
   ```

4. **확인하고 바로 실행(한 줄).** 프로젝트 쪽 셸에서 하네스 루트로 이동, 해시 확인, 실행을 한 명령으로 묶어 실행합니다. 확인과 실행 사이의 틈을 줄이기 위해서입니다(폴더도 이 실행만 쓰는 새 폴더입니다). `commit-checked.sh`는 현재 폴더가 하네스 루트 안이어야 하므로 맨 앞에 `cd "<루트>" &&`를 붙입니다. SKILL.md 실행 줄에서 스크립트 경로만 `<폴더>/<이름>`으로 바꾸고, `"<루트>"`, 메시지, `--allow`, `--` 뒤 경로 같은 나머지 인자는 그대로 둡니다. 옮긴 파일이 둘이면 두 줄을 모두 넣습니다.

   ```bash
   cd "<루트>" && printf '%s  %s\n' '<기대 해시>' '<폴더>/<이름>' | sha256sum -c - && bash "<폴더>/<이름>" "<루트>" …
   ```

   `commit-checked.sh`처럼 두 파일을 옮겼으면 해시 줄을 둘 다 넣습니다(세 파일이면 세 줄).

   ```bash
   cd "<루트>" && printf '%s  %s\n' '<해시1>' '<폴더>/commit-checked.sh' '<해시2>' '<폴더>/check-staged.sh' | sha256sum -c - && bash "<폴더>/commit-checked.sh" "<루트>" "<메시지>" …
   ```

   `sha256sum` 명령이 없다는 오류면 `shasum -a 256 -c -`로 바꿉니다. 해시가 맞으면 `<폴더>/<이름>: OK` 줄 아래에 스크립트 출력이 나오고, 결과는 SKILL.md의 규칙대로 읽습니다(`OK` 줄은 판정에 쓰지 않습니다). 해시가 다르면 `FAILED`가 나오고 스크립트는 실행되지 않습니다. 그때는 2~4단계를 새 폴더로 한 번만 다시 하고, 그래도 다르면 멈춥니다.

## 덧붙임
- 사용자에게는 "검사 도구를 이 폴더 쪽으로 옮겨, 원본과 같은지 확인한 뒤 실행했습니다" 정도로 한 줄만 알립니다.
