# co — 체크아웃

세션을 종료할 때 작업 내용을 분류하여 적절한 파일에 저장하고, git으로 백업합니다.

## 언제 사용

- 오늘 작업을 마무리할 때
- 새 세션으로 옮겨갈 때
- 중간 정리가 필요할 때

## 프로세스

### 0. 상태 감지

WHY: 하네스가 없으면 저장할 곳이 없다.

CLAUDE.md 파일에서 `<!-- non-dev-harness:` 마커 확인:
- 마커 없음 → "하네스가 없습니다. /hs 로 먼저 세팅하세요." → 종료
- 마커 있음 → 계속

### 1. 컨텍스트 수집

WHY: 저장할 내용이 무엇인지 파악해야 올바른 파일에 분류할 수 있다.

- 5개 파일 존재 확인: 없는 파일은 `~/.claude/plugins/non-dev-harness/templates/`에서 재생성
- 존재하는 파일만 읽기 (MEMORY.md "마지막 세션"만 전체, 나머지는 미해결 섹션만)
- `git diff --stat` (이번 세션에서 변경된 파일 목록)
- 대화 맥락 분석: 이번 세션에서 결정한 것, 배운 것, 발생한 에러, 발견한 이슈

### 2. 분류

WHY: 정보를 올바른 파일에 넣어야 다음 체크인에서 의미 있게 복원된다.

세션 내용을 6가지 유형으로 분류한다:

| 내용 유형 | 대상 파일 | 기준 |
|----------|----------|------|
| 새 규칙/관례 | CLAUDE.md "프로젝트 규칙" | 프로젝트 고유, 반복 적용되는 것만 |
| 결정, 맥락 | MEMORY.md "의사결정 이력" | 왜 A를 선택했는지 + 대안 |
| 세션 요약 + TODO | MEMORY.md "마지막 세션" (덮어쓰기) | 오늘 한 일 + 다음에 할 일 |
| 에러 + 해결 | ERROR.md | 유형 태그 + 시도한 복구 포함 |
| 새 이슈/버그 | ISSUE.md "미해결" | 우선순위(🔴🟡🟢) 부여 |
| 영구 지식 | WIKI.md | 프로젝트 고유 학습, 재현 불가 지식 |

포함 기준 (Anthropic 가이드라인):
- 프로젝트 고유한 것
- 재현 불가능한 학습
- 환경 특이사항

제외 기준:
- 일반 상식 (누구나 아는 것)
- 1회성 에러 (재발 가능성 없음)
- 코드에서 바로 읽히는 것

CLAUDE.md에 규칙 추가 시: 반드시 1줄로 압축. 긴 설명 금지.

### 3. 미리보기 → 사용자 확인

WHY: 사용자가 저장 내용을 확인해야 원치 않는 정보가 기록되지 않는다.

```
━━━━━━━━━━━━━━━━━━━━━━
체크아웃 정리

MEMORY.md:
  세션 요약: [요약]
  다음 할 일: [TODO]
  의사결정: [N건]

ERROR.md: 새 에러 [N] / 해결 [N]
ISSUE.md: 새 이슈 [N] / 해결 [N]
WIKI.md: 새 지식 [N건]
CLAUDE.md: 규칙 추가 [N] / 변경이력 갱신
━━━━━━━━━━━━━━━━━━━━━━
저장할까요?
```

사용자 확인 후에만 저장 진행. 수정 요청이 있으면 반영.

### 4. 저장

WHY: 해당 섹션만 수정해야 기존 내용이 보존된다 (Surgical Edit).

각 파일에 대해 Edit 도구로 해당 섹션만 수정한다. 파일이 없으면 템플릿에서 Write로 재생성 후 Edit:

- **MEMORY.md**: "## 마지막 세션" ~ "## 의사결정 이력" 사이를 덮어쓰기. "## 세션 로그" 아래에 항목 추가
- **ERROR.md**: "## 미해결" 테이블 끝에 행 추가. 해결된 건 "## 해결됨" 테이블로 이동
- **ISSUE.md**: "## 미해결" 테이블 끝에 행 추가. 해결된 건 "## 해결됨" 테이블로 이동
- **WIKI.md**: "## 일반/기술/워크플로우/교훈" 중 적절한 섹션에 추가
- **CLAUDE.md**: "## 프로젝트 규칙" 섹션에 규칙 추가 + "## 변경이력" 테이블에 행 추가

상한 초과 처리:
- MEMORY.md 세션 로그 5개 초과 → "오래된 로그를 WIKI.md '세션 아카이브'로 옮길까요?"
- ERROR.md 미해결 10개 초과 → "오래된 에러를 WIKI.md '교훈'으로 정리할까요?"
- ERROR.md 해결됨 20개 초과 → 오래된 해결 기록을 WIKI.md '교훈'으로 아카이브 제안
- ISSUE.md 미해결 15개 초과 → "낮은 우선순위 이슈를 WIKI.md로 옮길까요?"
- ISSUE.md 해결됨 30개 초과 → 오래된 해결 기록을 WIKI.md '세션 아카이브'로 아카이브 제안
- CLAUDE.md 100줄 초과 → "규칙이 많아졌어요. WIKI.md로 옮길 항목 있을까요?"

### 5. 진화

WHY: 프로젝트가 성장하면서 하네스도 함께 발전해야 한다.

- CLAUDE.md "변경이력" 테이블에 오늘 변경 사항 추가
- 해결된 에러에서 반복 패턴 발견 시: "이 교훈을 WIKI.md에 기록할까요?"

### 6. Git 저장 (전체 프로젝트)

WHY: "백업"은 하네스 파일뿐 아니라 작업물 전체를 의미한다. 비개발자가 의식하지 않아도 작업이 안전하게 기록되어야 한다.

git repo인 경우:
1. `git status --short` 확인 → 시크릿 파일 감지 (`.env*`, `*.pem`, `*.key`, `credentials*`, `secret*`)
   - 시크릿 파일 발견 → 경고 + .gitignore에 추가 제안
2. `git add -A` → "오늘 작업을 기록에 저장할까요?" (기본값: 예)
3. `git commit -m "co: 세션 체크아웃 — [날짜] [세션 요약 한 줄]"`
4. remote 있으면 → "클라우드에 백업할까요?" (기본값: 예) → `git push`

git repo가 아닌 경우:
- "/hs 로 기록 시스템을 켤 수 있어요."

.gitignore가 불필요 파일을 자동 제외 (hs에서 생성됨).

### 7. 체크아웃 요약

```
━━━━━━━━━━━━━━━━━━━━━━
체크아웃 완료

저장됨: [업데이트된 파일 목록]
기록됨: [git commit 메시지 또는 "(git 미사용)"]
백업됨: [push 완료 / 스킵 / "(remote 없음)"]

다음 세션: /ci 로 시작하세요
━━━━━━━━━━━━━━━━━━━━━━
```

## 흔한 실수

| 변명 | 현실 |
|------|------|
| "나중에 정리하면 돼" | 다음 세션에서 맥락이 사라져 처음부터 다시 설명해야 함 |
| "별로 한 게 없어서 저장 안 해도 돼" | 작은 결정도 기록해야 다음에 같은 고민 반복 안 함 |
| "git은 나중에" | 체크아웃이 곧 백업 시점. 미루면 작업물 유실 위험 |
| "MEMORY.md에 다 넣으면 되지" | 에러는 ERROR.md, 이슈는 ISSUE.md. 분류해야 찾기 쉬움 |

## 위험 신호

- [ ] 하네스 마커 확인 없이 바로 진행
- [ ] 미리보기 없이 바로 저장 시도
- [ ] 파일 전체를 Write로 덮어쓰기 (Edit로 해당 섹션만 수정해야 함. 파일 없을 때만 Write)
- [ ] "다음 할 일"을 비워둠
- [ ] 에러 기록에 유형 태그 누락
- [ ] 시크릿 파일(.env*, .pem, .key) 커밋 시도
- [ ] git commit 없이 종료 (사용자가 명시적 거부한 경우 제외)

## 확인 사항

- [ ] 하네스 마커 확인됨
- [ ] 5개 파일 모두 존재 (없으면 재생성됨)
- [ ] MEMORY.md "마지막 세션" 날짜 = 오늘
- [ ] MEMORY.md "다음 할 일" 비어있지 않음
- [ ] 변경된 파일 모두 저장됨
- [ ] 시크릿 파일 커밋 방지 확인
- [ ] git commit 완료 (repo인 경우)
- [ ] 체크아웃 요약 출력됨
