# co — 체크아웃

세션을 종료할 때 작업 내용을 분류하여 적절한 파일에 저장하고, git으로 백업합니다.

## 절대 규칙

- 미리보기 본문은 질문 도구를 부르기 **전에** 일반 글로 출력합니다. 질문 문장에도 핵심(고칠 파일, 올릴 파일, 커밋 메시지)을 넣습니다. 미리보기를 실제로 출력하지 않았으면 "위 미리보기"라고 쓰지 않습니다.
- git 저장은 하네스 루트 안에서만 합니다. 올라갈 목록을 보여 주고 한 번 확인받은 뒤 `git add -A -- <루트>`로 스테이징하고, 비밀 파일 이름, 비밀 키 내용, 50MB 넘는 크기를 검사합니다. 검사에 걸리거나 검사가 실패하면 `git reset -q -- <루트>`로 스테이징을 되돌리고 커밋하지 않습니다.
- 강제 push(`--force`, `--force-with-lease`)는 어떤 경우에도 하지 않고, push가 거절된 뒤 pull·merge·rebase도 스스로 하지 않습니다. 상황을 설명하고 멈춥니다.
- 기록 파일은 Edit로 해당 섹션만 고치고, 없는 기록 파일은 만들지 않습니다. git 사용자 정보가 비어 있으면 사용자에게 물어 `git config --local`로만 설정하고, 이름·이메일을 지어 넣지 않습니다.

## 도구 쓰는 법

- 사용자가 고르는 질문은 모두 선택지 질문 도구(AskUserQuestion)로 묻습니다. 도구가 없을 때만 번호 목록 글로 묻습니다. 한 번에 한 주제씩 묻습니다.
- 파일 읽기는 Read·Glob·Grep 도구로만 합니다. 하네스 표식 찾기와 기록 파일 읽기에 Bash `head`·`cat`·`for`·`while`·변수를 쓰지 않습니다.
- Cowork처럼 Read·Glob·Grep·Edit·Write가 프로젝트 폴더에 닿지 않는 환경에서는, 그 환경에서 프로젝트 폴더를 다루는 파일 도구를 같은 원칙(파일 하나씩, 고칠 부분만)으로 씁니다. 그런 도구도 없을 때만 프로젝트 쪽 셸에서 파일 하나씩 `cat "<파일>"`로 읽습니다.
- 검사 스크립트는 본문의 한 줄을 단독으로 실행합니다. 앞뒤에 `cd`·`&&`·`;`·파이프·변수를 붙이지 않습니다.
- git 명령의 경로는 변수에 담지 않고 하나씩 따옴표로 감싸 적습니다.
- 사용자에게 보이는 문장은 진행 안내까지 모두 한국어로 씁니다.
- "references의 X를 읽는다"는 `${CLAUDE_SKILL_DIR}/references/X`를 Read로 읽고 그대로 따른다는 뜻입니다.

## 프로세스

### 0. 상태 감지

현재 폴더부터 위로 올라가며 Read 도구로 각 폴더의 `CLAUDE.md`를 직접 열어(없으면 한 단계 위로, Bash `find`·`ls` 금지) 첫 줄이 `<!-- non-dev-harness:`로 시작하는 첫 폴더를 하네스 루트(`<루트>`)로 정합니다. 홈 폴더에 닿으면 멈추고 홈 자체는 검사하지 않습니다. 자동으로 실린 CLAUDE.md는 HTML 주석이 지워져 있으므로 판단에 쓰지 않습니다.

**위험 폴더 목록.** (가) 홈 폴더 자체, 드라이브 루트(`/`, `C:\`, Git Bash에서는 `/c`), `/Users`·`/home`·`C:\Users` 자체, `~/.claude`와 그 하위. (나) 홈 바로 아래의 Desktop·Documents·Downloads·바탕화면·문서·다운로드 폴더 자체, OneDrive 폴더 자체와 그 바로 아래의 Desktop·Documents·바탕 화면·문서 폴더.

- 찾음: 루트가 (가)에 들면 아무것도 저장하지 않고 멈춘 뒤, 범위가 넓어 개인 파일까지 기록될 수 있다고 설명합니다. (나)에 들면 1~5단계는 그대로 하되, 6단계 전에 위험과 옮기는 방법(새 프로젝트 폴더에 하네스 파일과 작업 파일을 옮기고 그 폴더에서 /hs)을 알리고, 사용자가 그래도 저장하겠다고 분명히 고를 때만 git 저장을 합니다.
- 못 찾음: references의 `no-harness-fallback.md`를 읽고 따릅니다. 기록 파일 5개는 만들지 않습니다.

### 1. 컨텍스트 수집

- **일지 파일**: JOURNAL.md가 있으면 그것을, 없고 하네스 형식 MEMORY.md(첫 줄이 `— 메모리`로 끝남)가 있으면 MEMORY.md를 일지로 읽고 씁니다. MEMORY.md를 쓴 경우 체크아웃 요약 끝에 "/hs로 v2 업데이트할 수 있어요"를 한 줄 안내합니다. 아래에서 JOURNAL.md는 이 일지 파일을 뜻합니다.
- 5개 파일(CLAUDE.md, JOURNAL.md, ERROR.md, ISSUE.md, WIKI.md)이 있는지 Glob 도구로 확인하고, Read 도구로 읽습니다. 없는 파일에 갈 내용은 미리보기에 "파일 없음"으로 표시하고, "/hs로 업데이트하면 빠진 파일을 만들어 줍니다"라고 안내합니다.
- 필요한 부분만 읽습니다: JOURNAL.md "마지막 세션", ERROR.md·ISSUE.md "미해결", WIKI.md "목차", CLAUDE.md "프로젝트 규칙"·"변경이력". 적을 섹션이 없으면 새로 만들 위치를 정해 미리보기에 함께 보여 줍니다.
- `git -c core.quotePath=false status --short -uall -- "<루트>"`로 바뀐 파일을 보고, 대화에서 결정·배운 점·에러·이슈를 정리합니다.

### 2. 분류

| 내용 유형 | 대상 파일 | 기준 |
|----------|----------|------|
| 새 규칙/관례 | CLAUDE.md "프로젝트 규칙" | 프로젝트 고유, 반복 적용되는 것만. 1줄로 |
| 결정, 맥락 | JOURNAL.md "의사결정 이력" | 왜 A를 선택했는지 + 대안 |
| 세션 요약 + 다음 할 일 | JOURNAL.md "마지막 세션" (본문 교체) | 오늘 한 일 + 다음에 할 일 |
| 에러 + 해결 | ERROR.md | 유형 태그 + 시도한 복구 포함 |
| 새 이슈/버그 | ISSUE.md "미해결" | 우선순위(🔴🟡🟢) 부여 |
| 영구 지식 | WIKI.md | 프로젝트 고유 학습, 재현 불가 지식 |

**대화에 있는 것만 적기.** 모든 칸은 사용자가 실제로 말했거나 대화에 나온 내용으로만 채웁니다. 의사결정의 "이유"와 "대안"도 그렇게 하고, 없으면 `-`로 둡니다("(논의 안 함)" 같은 짐작을 적지 않음).

**다음 할 일 이어받기.** 지난 "다음 할 일" 가운데 이번 세션에서 끝낸 항목만 뺍니다(`없음`, `(아직 없음)`은 할 일이 아니므로 이어 적지 않습니다). 끝내지 못한 항목은 새 "다음 할 일"에 이어 적거나 ISSUE.md "미해결"로 옮기고, 지우려면 사용자에게 먼저 묻습니다. 포함·제외 기준이 애매하면 references의 `classification-rules.md`를 읽습니다.

### 3. 미리보기 → 사용자 확인

질문 도구를 부르기 **전에** 아래 형식의 미리보기를 일반 글로 출력합니다(생각 요약 한 줄로 대신하지 않습니다). 각 파일에 실제로 적을 문장(세션 요약, 다음 할 일, 결정, 규칙)을 그대로 보여 줍니다.

```
━━━━━━━━━━━━━━━━━━━━━━
체크아웃 정리

JOURNAL.md:
  세션 요약: [요약]
  다음 할 일: [목록] (지난 할 일 이어 적음 [N] / ISSUE로 옮김 [N] / 지울지 확인 [N])
  의사결정: [N건]

ERROR.md: 새 에러 [N] / 해결 [N]
ISSUE.md: 새 이슈 [N] / 해결 [N]
WIKI.md: 새 지식 [N건] (목차에도 추가)
CLAUDE.md: 규칙 추가 [N] / 변경이력 [행 추가 / 없음]
새로 만들 섹션: [파일과 위치 / 없음]
파일 없음: [이름 — /hs로 업데이트하면 만들어 줍니다 / 없음]
━━━━━━━━━━━━━━━━━━━━━━
```

질문 문장 자체에 핵심을 넣어, 글을 못 봐도 무엇을 고르는지 알 수 있게 합니다: "JOURNAL.md에 '<요약 한 줄>', 다음 할 일 N개, 결정 N건을 적고 ERROR/ISSUE/WIKI에 N건을 더합니다. 저장할까요?" 선택지는 저장 / 고칠 부분 있음 / 저장 안 함입니다. 선택지 설명에는 "위 내용", "위 미리보기"처럼 앞 글을 가리키는 말을 쓰지 않고 질문 문장을 기준으로 씁니다(예: 저장 — "질문에 적은 내용대로 기록 파일을 고칩니다"). 질문 도구를 부르면 앞의 글이 화면에서 생략될 수 있기 때문입니다. "저장"일 때만 4단계로 갑니다. 고칠 부분이 있으면 반영해 다시 보여 주고, "저장 안 함"이면 기록 파일은 건드리지 않고 6단계로 갑니다(6단계에서 다시 묻습니다).

### 4. 저장

Edit 도구로 해당 섹션만 고칩니다. 섹션이 없던 곳은 미리보기에서 확인받은 위치에 만듭니다.

- **JOURNAL.md**: "## 마지막 세션"의 본문을 다음 `##` 전까지 바꿉니다(`- 날짜:`, `- 요약:`, `- 다음 할 일:` 아래 하위 목록. 정해진 할 일이 없으면 하위 목록에 `  - 없음` 한 줄). "## 의사결정 이력" 표 끝에 행을 붙이고, "## 세션 로그" 맨 아래에 `- YYYY-MM-DD — 한 줄 요약`을 추가합니다.
- **ERROR.md·ISSUE.md**: "## 미해결" 표 끝에 행 추가. 해결된 건 "## 해결됨" 표로 이동
- **WIKI.md**: 알맞은 섹션(일반/기술/워크플로우/교훈)에 추가하고, "## 목차"에 `- [섹션] 제목` 한 줄을 함께 추가합니다.
- **CLAUDE.md**: "## 프로젝트 규칙"에 규칙을 1줄로 추가합니다. "## 변경이력" 표에는 규칙이나 하네스 구조가 바뀐 날에만 행을 추가합니다.

상한: JOURNAL.md 세션 로그 5개, ERROR.md 미해결 10개·해결됨 20개, ISSUE.md 미해결 15개·해결됨 30개, CLAUDE.md 변경이력 10행·전체 100줄. 넘으면 references의 `classification-rules.md` "상한을 넘었을 때"를 읽고 옮길지 묻습니다.

### 5. 진화

- 해결된 에러에서 반복 패턴이 보이면 "이 교훈을 WIKI.md에 기록할까요?"라고 묻습니다.

### 6. Git 저장 (하네스 루트)

git 저장소가 아니면(`git rev-parse --is-inside-work-tree` 실패) "/hs 로 작업 기록(git)을 켤 수 있어요."라고 안내하고 7단계로 갑니다. `.gitignore`가 있다고 가정하지 않습니다.

쓰기 명령(add, reset, rm --cached, config --local, commit, push)은 **현재 폴더가 하네스 루트일 때** `-C` 없이 본문에 적힌 모양 그대로 실행합니다. 그중 add, reset, 이 폴더의 사용자 정보 설정, 그리고 6-4의 검사·커밋 스크립트는 사전 승인되어 확인 창 없이 지나갑니다. 커밋은 6-4의 스크립트로만 합니다(bash가 없을 때만 `flagged-files.md`의 예외를 따름). 현재 폴더가 하네스 루트가 아니면(하위 폴더에서 시작했거나, 현재 폴더가 루트와 다른 저장소) 같은 명령에 `-C "<루트>"`를 붙여 `git -C "<루트>" …`로 실행하고, 이때는 확인 창이 뜹니다. `git`과 하위 명령 사이에 `-c` 같은 다른 옵션을 넣지 않습니다. 목록·설정·원격·추적 여부를 보는 읽기 명령(status, diff --cached, config --get, remote, rev-parse, rev-list, ls-files)은 사전 승인이 맞도록 **현재 폴더에서 `-C` 없이, 본문에 적힌 모양 그대로** 실행합니다. Cowork 파일 삭제 허용 창, `index.lock` 오류, 커밋·push 실패, "outside repository" 오류가 나면 references의 `git-troubleshooting.md`를 읽고 따릅니다.

6-1. **목록 보여 주고 묻기**: 현재 폴더에서 `-C` 없이 `git -c core.quotePath=false status --short -uall -- "<루트>"`를 그대로 실행해 올라갈 파일 목록을 얻습니다. 50개가 넘으면 `-uall`을 빼고(새 폴더를 한 줄로 접음) 폴더별 목록과 전체 개수를 보여 줍니다. `git diff --cached --name-only`에 루트 밖 파일이 있으면 그 파일도 함께 커밋된다고 덧붙입니다. 질문 도구를 부르기 **전에** 목록을 일반 글로 출력하고, 질문 문장에 개수와 앞 몇 개 파일 이름, 커밋 메시지를 넣습니다("파일 N개(JOURNAL.md, notes/plan.md …)를 'co: 세션 체크아웃 — …'로 기록할까요?"). 선택지는 정확히 **올리기 / 멈추기** 두 개입니다. 파일을 미리 골라 빼는 선택지를 만들지 않습니다(비밀 파일 판단은 6-4 검사 스크립트가 합니다). 확인은 이 한 번뿐입니다. 목록이 비었으면 "기록할 변경이 없습니다"라고 알립니다. 이때 원격에 아직 올리지 못한 커밋이 있으면(`git rev-parse --abbrev-ref --symbolic-full-name @{u}`가 성공하고 `git rev-list --count @{u}..HEAD`가 0보다 큼, 또는 upstream이 없는데 `git remote` 출력이 있고 `git rev-parse --verify HEAD`가 성공함) 6-2~6-5를 건너뛰고 6-6 push로 갑니다. 그 밖에 비었거나 멈추기면 스테이징하지 않고 7단계로 갑니다.
6-2. **사용자 정보**: `git config --get user.name`이나 `git config --get user.email`이 비어 있으면 사용자에게 묻고 `git config --local user.name "<이름>"`, `git config --local user.email "<이메일>"`로 설정합니다. 답하지 않으면 스테이징하지 않고 7단계로 갑니다.
6-3. **스테이징**: `git add -A -- "<루트>"`
6-4. **검사와 커밋**: 아래 한 줄만 단독으로 실행합니다. 이 스크립트가 지금 스테이징된 내용을 고정해 비밀 파일 검사를 돌리고, 통과했을 때만 검사한 그대로 커밋합니다(git 훅은 실행하지 않습니다). `git commit`을 따로 실행하지 않습니다. 현재 폴더가 하네스 루트 안이어야 합니다.

```bash
bash "${CLAUDE_SKILL_DIR}/scripts/commit-checked.sh" "<루트>" "co: 세션 체크아웃 — YYYY-MM-DD 한 줄 요약"
```

   - 메시지 인자는 위 한 줄 제목만 씁니다. 줄바꿈을 넣지 않습니다(줄바꿈이 든 명령은 사전 승인과 맞지 않아 확인 창이 뜹니다). 환경이 붙이라고 안내하는 `Co-Authored-By:` 줄은 메시지 뒤에 `--trailer "<그 줄 그대로>"`(예: `--trailer "Co-Authored-By: Claude <noreply@anthropic.com>"`)로 한 줄씩 넘기면 스크립트가 빈 줄 뒤에 붙입니다. `Claude-Session:` 줄은 메시지에도 `--trailer`에도 넣지 않습니다(넣으면 스크립트가 종료 코드 2로 거부합니다).
   - 종료 코드가 0이고 마지막 줄이 `[커밋] <해시> <제목>`이면 커밋된 것입니다. 6-5로 갑니다.
   - 종료 코드 4(`[커밋 안 함] 걸린 파일이 있습니다`): `[이름]`, `[내용]`, `[크기]` 머리말 아래에 걸린 파일이 `:(top)경로`로 나옵니다. 즉시 `git reset -q -- "<루트>"`로 스테이징을 되돌린 뒤 references의 `flagged-files.md`를 읽고 따릅니다.
   - 종료 코드 3(검사가 끝까지 돌지 않음)이나 5(커밋할 변경이 없음, 작성자 정보 없음, 서명 실패, 진행 중인 병합·리베이스, 브랜치가 아닌 곳(분리된 HEAD), 실행 중에 브랜치가 바뀜 등 커밋 실패): 커밋은 되지 않았습니다. `git reset -q -- "<루트>"`로 스테이징을 되돌리고 오류 문장을 보여 줍니다. 3이면 `flagged-files.md`의 "검사가 실패했을 때", 5면 `git-troubleshooting.md`를 따릅니다. 직접 판단으로 대신하지 않습니다.
   - 종료 코드 2: 메시지 오류(예: `Claude-Session:` 줄)면 고쳐서 한 번만 다시 실행합니다. 루트 오류("하네스 루트가 아닙니다", "현재 폴더가 하네스 루트 안이 아닙니다")면 다시 시도하지 않고 스테이징을 되돌린 뒤, 하네스 폴더에서 Claude Code를 열어 /co를 다시 하라고 안내합니다.
   - 셸이 이 스크립트 파일을 찾지 못하거나 열지 못했다는 오류(`…/commit-checked.sh: No such file or directory` 또는 `…/commit-checked.sh: Permission denied`)만 나왔으면 스테이징을 되돌리지 않은 채 references의 `run-script-elsewhere.md`를 읽고 그 절차로 옮겨 실행합니다(Cowork에서 생김). 결과는 이 단계의 규칙대로 읽고, 그 절차가 멈추면 종료 코드 3과 같이 처리합니다.
   - 셸이 `bash` 명령 자체를 찾지 못했다는 오류(예: `command not found: bash`)와 종료 코드 127이 함께 나왔을 때만 bash 없음으로 봅니다. 이때만 스테이징을 그대로 둔 채 references의 `flagged-files.md` "bash가 없을 때만" 절을 읽고 직접 확인합니다.
   - 되돌리기 권한 창을 사용자가 거절하면, 걸린 파일이 아직 커밋 목록(스테이징)에 올라가 있다고 알리고 다른 도구로 커밋하지 말라고 안내한 뒤 멈춥니다.
6-5. **커밋 확인**: `[커밋]` 줄의 해시와 제목을 7단계 요약에 씁니다. 경로를 지정해 따로 커밋하지 않습니다(지정하면 `git rm --cached`로 뺀 파일이 디스크에서 도로 담깁니다).
6-6. **push**: `git remote` 출력이 있으면 "GitHub(클라우드)에도 올릴까요?"라고 묻습니다(올리기 / 이번엔 안 함). 원격은 하나면 그 이름, 여럿이면 `origin`, `origin`이 없으면 사용자에게 묻습니다. upstream이 없으면(`git rev-parse --abbrev-ref --symbolic-full-name @{u}` 실패) `git push -u <원격 이름> HEAD`, 있으면 `git push`. 6-1에서 새 변경 없이 넘어왔으면 질문에 "이 저장소의 올리지 못한 커밋 N개 전체가 올라갑니다"를 넣습니다(N은 `git rev-list --count @{u}..HEAD`, upstream이 없으면 `git rev-list --count HEAD`). 현재 폴더에서 `-C` 없이 실행한 `git rev-parse --show-prefix` 출력이 비어 있지 않으면 이 폴더가 더 큰 저장소의 일부이니, 이 폴더 밖의 커밋까지 그 저장소 전체가 올라간다고 함께 알립니다.
