# co — 체크아웃

세션을 종료할 때 작업 내용을 분류하여 적절한 파일에 저장하고, git으로 백업합니다.

## 절대 규칙

- 미리보기 본문은 질문 도구를 부르기 **전에** 일반 글로 출력합니다. 질문 문장에도 핵심(고칠 파일, 올릴 파일, 커밋 메시지)을 넣습니다. 미리보기를 실제로 출력하지 않았으면 "위 미리보기"라고 쓰지 않습니다.
- git 저장은 하네스 루트 안에서만 합니다. 올라갈 목록을 보여 주고 한 번 확인받은 뒤 `git add -A -- <루트>`로 스테이징하고, 비밀 파일 이름, 비밀 키 내용, 50MB 넘는 크기를 검사합니다. 검사에 걸리면 `git reset -q -- <루트>`로 스테이징을 되돌리고 커밋하지 않습니다.
- 강제 push(`--force`, `--force-with-lease`)는 어떤 경우에도 하지 않고, push가 거절된 뒤 pull·merge·rebase도 스스로 하지 않습니다. 상황을 설명하고 멈춥니다.
- 기록 파일은 Edit로 해당 섹션만 고치고, 없는 기록 파일은 만들지 않습니다. git 사용자 정보가 비어 있으면 사용자에게 물어 `git config --local`로만 설정하고, 이름·이메일을 지어 넣지 않습니다.

## 도구 쓰는 법

- 사용자가 고르는 질문은 모두 선택지 질문 도구(AskUserQuestion)로 묻습니다. 도구가 없을 때만 번호 목록 글로 묻습니다. 한 번에 한 주제씩 묻습니다.
- 파일 읽기는 Read·Glob·Grep 도구로만 합니다. 하네스 표식 찾기와 기록 파일 읽기에 Bash `head`·`cat`·`for`·`while`·변수를 쓰지 않습니다.
- 검사 스크립트는 본문의 한 줄을 단독으로 실행합니다. 앞뒤에 `cd`·`&&`·`;`·파이프·변수를 붙이지 않습니다.
- git 명령의 경로는 변수에 담지 않고 하나씩 따옴표로 감싸 적습니다.
- 사용자에게 보이는 문장은 진행 안내까지 모두 한국어로 씁니다.

## 언제 사용

- 오늘 작업을 마무리할 때
- 새 세션으로 옮겨갈 때
- 중간 정리가 필요할 때

## 프로세스

### 0. 상태 감지

WHY: 하네스가 있으면 5개 파일에 나눠 저장하고, 없으면 프로젝트에 이미 있는 기록처에 맞춘다.

현재 폴더부터 한 단계씩 위로 올라가며 각 폴더의 CLAUDE.md 첫 줄을 Read나 Grep 도구로 파일에서 직접 읽습니다. 첫 줄이 `<!-- non-dev-harness:`로 시작하는 CLAUDE.md를 처음 만난 폴더가 하네스 루트입니다. 홈 폴더에 닿으면 멈추고, 홈 폴더 자체는 검사하지 않습니다. 대화에 자동으로 실린 CLAUDE.md에는 HTML 주석이 지워져 있으므로 그것으로 판단하지 않습니다. 아래의 기록 파일 경로와 `<루트>`는 모두 이 하네스 루트를 기준으로 합니다.

**위험 폴더 목록.** (가) 홈 폴더 자체, 드라이브 루트(`/`, `C:\`, Git Bash에서는 `/c`), `/Users`·`/home`·`C:\Users` 자체, `~/.claude`와 그 하위. (나) 홈 바로 아래의 Desktop·Documents·Downloads·바탕화면·문서·다운로드 폴더 자체, OneDrive 폴더 자체와 그 바로 아래의 Desktop·Documents·바탕 화면·문서 폴더.

- 찾음: 루트가 (가)에 들면 아무것도 저장하지 않고 멈춘 뒤, 이 폴더는 범위가 넓어 개인 파일까지 기록될 수 있다고 설명합니다. 루트가 (나)에 들면 1~5단계는 그대로 하고, 6단계 git 저장 전에 위험을 설명하고 옮기는 방법(새 프로젝트 폴더를 만들고 하네스 파일과 작업 파일을 옮긴 뒤 그 폴더에서 /hs)을 안내하며, 사용자가 그래도 저장하겠다고 분명히 고를 때만 git 저장을 합니다. 그 밖이면 1단계로 갑니다.
- 못 찾음: **대체 분기**로 갑니다. 5개 파일을 만들지 않습니다. 이번 세션의 결정, 배운 점, 에러, 남은 일을 정리하고, 프로젝트에 이미 있는 기록처(README, 기존 노트나 변경 기록 파일)를 고릅니다. 알맞은 곳이 없으면 현재 폴더에 `NOTES.md` 하나만 만듭니다. 무엇을 어디에 적을지 글로 보여 주고 확인받은 뒤에만 저장합니다. 그다음 1~5단계를 건너뛰고, 현재 폴더를 `<루트>`로 삼아 6단계 git 저장으로 갑니다. 현재 폴더가 위험 폴더 목록 (가)나 (나)에 들면 git 저장은 건너뜁니다.

### 1. 컨텍스트 수집

WHY: 저장할 내용이 무엇인지 파악해야 올바른 파일에 분류할 수 있다.

- **일지 파일**: JOURNAL.md가 있으면 그것을, 없고 하네스 형식 MEMORY.md(첫 줄이 `— 메모리`로 끝남)가 있으면 MEMORY.md를 일지로 읽고 씁니다. MEMORY.md를 쓴 경우 체크아웃 요약 끝에 "/hs로 v2 업데이트할 수 있어요"를 한 줄 안내합니다. 아래에서 JOURNAL.md는 이 일지 파일을 뜻합니다.
- 5개 파일(CLAUDE.md, JOURNAL.md, ERROR.md, ISSUE.md, WIKI.md)이 있는지 확인합니다. 없는 파일은 만들지 않습니다. 그 파일에 갈 내용은 미리보기에 "파일 없음"으로 표시하고, "/hs로 업데이트하면 빠진 파일을 만들어 줍니다"라고 안내합니다.
- 있는 파일은 필요한 부분만 읽습니다. JOURNAL.md는 "마지막 세션" 전체, ERROR.md·ISSUE.md는 "미해결" 섹션, WIKI.md는 "목차", CLAUDE.md는 "프로젝트 규칙"과 "변경이력"입니다. 적을 섹션이 없으면(사용자가 구성을 바꾼 프로젝트) 새로 만들 위치를 정해 두고 미리보기에 함께 보여 줍니다.
- `git -c core.quotePath=false status --short -uall -- "<루트>"`로 이번 세션에서 바뀐 파일을 봅니다.
- 대화 맥락 분석: 이번 세션에서 결정한 것, 배운 것, 발생한 에러, 발견한 이슈

### 2. 분류

WHY: 정보를 올바른 파일에 넣어야 다음 체크인에서 의미 있게 복원된다.

세션 내용을 6가지 유형으로 분류한다:

| 내용 유형 | 대상 파일 | 기준 |
|----------|----------|------|
| 새 규칙/관례 | CLAUDE.md "프로젝트 규칙" | 프로젝트 고유, 반복 적용되는 것만 |
| 결정, 맥락 | JOURNAL.md "의사결정 이력" | 왜 A를 선택했는지 + 대안 |
| 세션 요약 + 다음 할 일 | JOURNAL.md "마지막 세션" (본문 교체) | 오늘 한 일 + 다음에 할 일 |
| 에러 + 해결 | ERROR.md | 유형 태그 + 시도한 복구 포함 |
| 새 이슈/버그 | ISSUE.md "미해결" | 우선순위(🔴🟡🟢) 부여 |
| 영구 지식 | WIKI.md | 프로젝트 고유 학습, 재현 불가 지식 |

**다음 할 일 이어받기.** 지난 "마지막 세션"의 "다음 할 일" 가운데 이번 세션에서 끝낸 항목만 뺍니다. 끝내지 못한 항목은 새 "다음 할 일"에 이어 적거나 ISSUE.md "미해결"로 옮깁니다. 끝내지 못한 항목을 지우려면 사용자에게 먼저 묻습니다.

포함 기준:
- 프로젝트 고유한 것
- 재현 불가능한 학습
- 환경 특이사항

제외 기준:
- 일반 상식 (누구나 아는 것)
- 1회성 에러 (재발 가능성 없음)
- 코드에서 바로 읽히는 것

CLAUDE.md에 규칙 추가 시: 반드시 1줄로 압축. 긴 설명 금지.

### 3. 미리보기 → 사용자 확인

WHY: 사용자가 저장 내용을 확인해야 원치 않는 정보가 기록되지 않는다.

아래 형식의 미리보기를 먼저 일반 글로 출력하고, 그다음에 질문 도구를 부릅니다. 각 파일에 실제로 적을 문장(세션 요약, 다음 할 일, 결정, 규칙)을 그대로 보여 줍니다.

```
━━━━━━━━━━━━━━━━━━━━━━
체크아웃 정리

JOURNAL.md:
  세션 요약: [요약]
  다음 할 일: [목록] (지난 할 일 이어 적음 [N] / ISSUE로 옮김 [N] / 지울지 확인 [N])
  의사결정: [N건]

ERROR.md: 새 에러 [N] / 해결 [N]
ISSUE.md: 새 이슈 [N] / 해결 [N]
WIKI.md: 새 지식 [N건] (목차에도 추가)
CLAUDE.md: 규칙 추가 [N] / 변경이력 [행 추가 / 없음]
새로 만들 섹션: [파일과 위치 / 없음]
파일 없음: [이름 — /hs로 업데이트하면 만들어 줍니다 / 없음]
━━━━━━━━━━━━━━━━━━━━━━
```

질문 문장에는 고칠 파일 이름을 넣고("JOURNAL.md, WIKI.md에 위 내용을 저장할까요?"처럼), 저장 / 고칠 부분 있음 / 저장 안 함 가운데 고르게 합니다. "저장"일 때만 4단계로 갑니다. 고칠 부분이 있으면 반영해 다시 보여 주고, "저장 안 함"이면 기록 파일은 건드리지 않고 6단계 git 저장으로 갑니다(6단계에서 다시 묻습니다).

### 4. 저장

WHY: 해당 섹션만 수정해야 기존 내용이 보존된다 (Surgical Edit).

각 파일에 대해 Edit 도구로 해당 섹션만 수정합니다. 파일 전체를 Write로 쓰지 않습니다. 섹션이 없던 곳은 미리보기에서 확인받은 위치에 만듭니다.

- **JOURNAL.md**: "## 마지막 세션"의 본문을 다음 `##` 전까지 바꿉니다. 형식은 `- 날짜:`, `- 요약:`, `- 다음 할 일:` 아래 하위 목록입니다. "## 의사결정 이력" 표 끝에 행을 붙이고, "## 세션 로그" 맨 아래에 `- YYYY-MM-DD — 한 줄 요약`을 한 줄 추가합니다.
- **ERROR.md**: "## 미해결" 표 끝에 행 추가. 해결된 건 "## 해결됨" 표로 이동
- **ISSUE.md**: "## 미해결" 표 끝에 행 추가. 해결된 건 "## 해결됨" 표로 이동
- **WIKI.md**: "## 일반/기술/워크플로우/교훈" 중 알맞은 섹션에 추가하고, "## 목차"에 `- [섹션] 제목` 한 줄을 함께 추가합니다.
- **CLAUDE.md**: "## 프로젝트 규칙"에 규칙을 1줄로 추가합니다. "## 변경이력" 표에는 규칙이나 하네스 구조가 바뀐 날에만 행을 추가합니다. 평소 작업만 한 날은 추가하지 않습니다.

상한 초과 처리:
- JOURNAL.md 세션 로그 5개 초과 → "오래된 로그를 WIKI.md '세션 아카이브'로 옮길까요?"
- ERROR.md 미해결 10개 초과 → "오래된 에러를 WIKI.md '교훈'으로 정리할까요?"
- ERROR.md 해결됨 20개 초과 → 오래된 해결 기록을 WIKI.md '교훈'으로 아카이브 제안
- ISSUE.md 미해결 15개 초과 → "낮은 우선순위 이슈를 WIKI.md로 옮길까요?"
- ISSUE.md 해결됨 30개 초과 → 오래된 해결 기록을 WIKI.md '세션 아카이브'로 아카이브 제안
- CLAUDE.md 변경이력 10행 초과 → "오래된 변경이력을 WIKI.md '세션 아카이브'로 옮길까요?" (최근 10행 유지)
- CLAUDE.md 100줄 초과 → "규칙이 많아졌어요. WIKI.md로 옮길 항목 있을까요?"

### 5. 진화

WHY: 프로젝트가 성장하면서 하네스도 함께 발전해야 한다.

- 해결된 에러에서 반복 패턴 발견 시: "이 교훈을 WIKI.md에 기록할까요?"

### 6. Git 저장 (하네스 루트)

WHY: "백업"은 하네스 파일뿐 아니라 작업물 전체를 의미한다. 다만 비밀 키와 큰 파일은 한 번 기록되거나 GitHub에 올라가면 되돌리기 어려우므로, 하네스 루트 안의 변경만 올리고 커밋 전에 검사한다.

git 저장소가 아니면(`git rev-parse --is-inside-work-tree` 실패) "/hs 로 작업 기록(git)을 켤 수 있어요."라고 안내하고 '7. 체크아웃 요약'으로 갑니다. `.gitignore`가 있다고 가정하지 않습니다.

**명령 실행 위치.** 스테이징, 되돌리기, 기록에서 빼기, 추적 여부 확인, 설정 쓰기, 커밋, push처럼 저장소를 바꾸거나 판단에 쓰는 명령은 `git -C "<루트>"`로 실행합니다. 목록·설정·원격을 보는 읽기 명령은 사전 승인이 맞도록 `-C` 없이 실행하되, "outside repository"로 실패하면 현재 폴더가 루트와 다른 저장소이므로 읽기 명령도 `git -C "<루트>"`로 다시 실행합니다.

**Cowork 확인 창.** Cowork에서 스테이징이나 커밋을 할 때 "이 폴더 안의 파일을 영구 삭제하도록 허용할까요?" 같은 확인 창이 뜰 수 있습니다. git이 기록을 저장하면서 이 프로젝트 폴더 안(`.git` 폴더)에 잠깐 만든 잠금 파일을 지우려는 것이고, 작업 파일을 지우는 것이 아니라고 쉬운 말로 설명합니다. 사용자가 허용하지 않으면 커밋을 건너뛰고 "기록 파일은 이 폴더에 저장되었습니다. git 기록은 내 컴퓨터의 터미널이나 Claude Code에서 /co를 다시 하면 남습니다"라고 안내한 뒤 '7. 체크아웃 요약'으로 갑니다.

**잠금 파일 복구.** git이 `index.lock`이 이미 있다고 실패하면(Cowork에서 삭제 허용을 거절한 뒤 포함), 다른 터미널이나 앱에서 git 작업이 돌고 있지 않은지 사용자에게 확인합니다. 돌고 있지 않다고 하면 허락을 받아 그 파일 하나(`<저장소>/.git/index.lock`)만 지우고 다시 진행합니다. 다른 파일은 지우지 않습니다.

6-1. **목록 보여 주고 묻기**: `git -c core.quotePath=false status --short -uall -- "<루트>"`로 올라갈 파일 목록을 얻고 줄 수를 셉니다. 50개가 넘으면 `-uall`을 뺀 `git -c core.quotePath=false status --short -- "<루트>"`(새 폴더를 한 줄로 접어 보여 줌)로 폴더별 목록을 보여 주고 전체 개수를 함께 알립니다. `git diff --cached --name-only`에 루트 밖 파일이 있으면, 사용자가 미리 스테이징해 둔 그 파일도 함께 커밋된다고 덧붙입니다. 목록을 글로 출력한 뒤, 개수와 커밋 메시지를 넣은 질문("파일 N개를 'co: 세션 체크아웃 — …'로 기록할까요?")으로 올리기 / 멈추기를 고르게 합니다. 확인은 여기서 한 번만 받습니다. 목록이 비어 있으면 "기록할 변경이 없습니다"라고 알리고, 사용자가 멈추기를 고르면 아무것도 스테이징하지 않습니다. 두 경우 모두 '7. 체크아웃 요약'으로 갑니다.
6-2. **사용자 정보**: `git config --get user.name`이나 `git config --get user.email`이 비어 있으면 이름과 이메일을 사용자에게 묻고 `git -C "<루트>" config --local user.name "<이름>"`, `git -C "<루트>" config --local user.email "<이메일>"`로 설정합니다. 사용자가 답하지 않으면 스테이징하지 않고 '7. 체크아웃 요약'으로 갑니다.
6-3. **스테이징**: `git -C "<루트>" add -A -- "<루트>"`
6-4. **검사**: 아래 한 줄만 단독으로 실행합니다.

```bash
bash "${CLAUDE_SKILL_DIR}/scripts/check-staged.sh" "<루트>"
```

   - 스테이징된 모든 파일(커밋에 들어갈 전부)을 검사합니다. `[이름]`, `[내용]`, `[크기]` 머리말 아래에 걸린 파일이 `:(top)경로` 모양으로 나오고, 비밀 값 자체는 나오지 않습니다. 이 경로는 아래 git 명령에 따옴표로 감싸 그대로 씁니다. 사용자에게 보여 줄 때는 `:(top)`을 떼고 보여 줍니다.
   - 마지막 줄 `[끝]`이 없거나 종료 코드가 0이 아니면 검사 실패입니다. 통과로 치지 않고 직접 확인으로 넘어갑니다.
   - 직접 확인: bash가 없거나 검사가 실패하면 스크립트를 Read로 열어 기준을 확인하고, `git diff --cached --name-only` 목록을 직접 보고 같은 기준으로 판단합니다. 내용은 Grep 도구를 파일 이름만 나오는 방식으로 써서 같은 패턴을 찾습니다. 직접 확인도 할 수 없으면 `git -C "<루트>" reset -q -- "<루트>"`로 스테이징을 되돌리고 멈춥니다.
   - 경로에 `${CLAUDE_SKILL_DIR}`가 치환되지 않은 채 보이면 이 SKILL.md와 같은 폴더의 `scripts/check-staged.sh`를 씁니다.
   - 한계: git이 바이너리로 보는 파일(UTF-16 텍스트, Office 문서 등)은 내용 검사를 하지 못합니다.
6-5. **걸리면 멈추기**: 머리말 아래에 경로가 하나라도 나오면 `git -C "<루트>" reset -q -- "<루트>"`로 스테이징만 되돌립니다(파일은 그대로 남습니다). 걸린 파일이 루트 밖에 있으면 그 파일도 `git -C "<루트>" reset -q -- "<걸린 경로>"`로 내립니다. 커밋하지 않고 멈춘 뒤 어떤 파일이 왜 걸렸는지 쉬운 말로 설명합니다.
   - 아직 기록된 적 없는 파일(`git -C "<루트>" ls-files -- "<걸린 경로>"` 결과가 비어 있음)이면 `.gitignore`에 그 파일이나 패턴을 추가하자고 제안합니다.
   - 이미 기록 중인 파일이면 `.gitignore`에 넣는 것만으로는 계속 올라간다고 설명하고, `.gitignore`에 넣는 것과 `git -C "<루트>" rm --cached -- "<걸린 경로>"`로 기록에서 빼는 것을 함께 하도록 안내합니다(컴퓨터의 파일은 지워지지 않습니다). 예전 기록에 이미 들어간 키는 남아 있으므로 키를 새로 발급받도록 권합니다.
   - 50MB가 넘는 파일은 기록을 무겁게 만들고 100MB부터는 GitHub가 받지 않는다고 설명하고 `.gitignore` 추가를 제안합니다.
   - 걸린 파일이 비밀이 아니라고 사용자가 분명히 말하면, 6-3부터 다시 하되 검사에 `--allow "<걸린 경로>"`를 붙여 그 파일을 뺍니다(`bash "${CLAUDE_SKILL_DIR}/scripts/check-staged.sh" "<루트>" --allow "<걸린 경로>"`). 뺀 파일 말고 걸린 것이 없으면 통과입니다.
   - 사용자가 정리를 마치면 6-3부터 다시 합니다. `.gitignore`를 고쳤다면 그 변경도 이번 커밋에 함께 들어간다고 알립니다.
6-6. **커밋**: 검사를 통과하면 다시 묻지 않고 바로 커밋합니다. 커밋에는 경로를 지정하지 않습니다. 경로를 지정하면 git이 디스크의 현재 내용을 다시 담아서, `git rm --cached`로 뺀 파일이 도로 들어갑니다.
   `git -C "<루트>" commit -m "co: 세션 체크아웃 — YYYY-MM-DD 한 줄 요약"`
   - 커밋 자체가 실패하면(작성자 정보 없음, 쓰기 권한 없음 등) 이미 저장한 기록 파일은 그대로 두고, "기록 파일은 이 폴더에 저장되었습니다. git 기록은 내 컴퓨터의 터미널이나 Claude Code에서 /co를 다시 하면 남습니다"라고 안내하고 '7. 체크아웃 요약'으로 갑니다.
6-7. **push**: `git remote` 출력이 있으면 "GitHub(클라우드)에도 올릴까요?"라고 묻습니다(올리기 / 이번엔 안 함). 원격이 하나면 그 이름을, 여럿이면 `origin`을 쓰고, 여럿인데 `origin`이 없으면 어느 곳에 올릴지 묻습니다.
   - upstream이 없으면(`git rev-parse --abbrev-ref --symbolic-full-name @{u}` 실패) `git -C "<루트>" push -u <원격 이름> HEAD`, 있으면 `git -C "<루트>" push`를 실행합니다.
   - push가 `Cowork blocked this request`로 막히면 실패로 다루지 않습니다. "기록은 이 폴더에 저장되었고, 클라우드 백업은 내 컴퓨터의 터미널이나 Claude Code에서 /co를 다시 하면 올라갑니다"라고 안내하고 끝냅니다.
   - push가 거절되면 "다른 컴퓨터나 GitHub 웹에서 먼저 올린 기록이 있을 수 있습니다. 이 컴퓨터의 커밋은 안전하게 남아 있습니다"라고 설명하고 멈춥니다. 로그인 만료나 큰 파일처럼 다른 이유로 실패해도 원인을 설명하고 멈춥니다.
