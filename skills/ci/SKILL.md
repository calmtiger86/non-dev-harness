# ci — 체크인

세션을 시작할 때 프로젝트 맥락을 로드하고 이전 작업 상태를 파악합니다.

## 도구 쓰는 법

- 4단계 브리핑 블록은 질문 도구를 부르기 **전에** 일반 글로 출력합니다(생각 요약 한 줄로 대신하지 않습니다).
- 사용자가 고르는 질문은 모두 선택지 질문 도구(AskUserQuestion)로 묻습니다. 도구가 없을 때만 번호 목록 글로 묻습니다.
- 파일 읽기는 Read·Glob·Grep 도구로만 합니다. 하네스 표식 찾기, README와 기록 파일 읽기에 Bash `head`·`cat`·`for`·`while`·변수를 쓰지 않습니다.
- 상태 스크립트는 3단계의 한 줄을 단독으로 실행합니다. 앞뒤에 `cd`·`&&`·`;`·파이프·변수를 붙이지 않습니다. 그래야 권한 확인 창 없이 실행됩니다.
- 사용자에게 보이는 문장은 진행 안내까지 모두 한국어로 씁니다.

## 언제 사용

- 새 세션을 시작할 때 (가장 먼저)
- 이전 작업을 이어서 할 때
- 프로젝트 상태를 확인하고 싶을 때

## 프로세스

### 1. 상태 감지

WHY: 하네스가 있으면 5개 기록 파일로, 없으면 프로젝트 자체 기록으로 브리핑한다. 하네스가 없는 프로젝트에서도 체크인은 쓸모가 있다.

현재 폴더부터 한 단계씩 위로 올라가며 Read 도구로 각 폴더의 `CLAUDE.md`를 직접 열어 첫 줄을 봅니다(파일이 없으면 한 단계 위로). Bash `find`·`ls`로 찾지 않습니다. 첫 줄이 `<!-- non-dev-harness:`로 시작하는 CLAUDE.md를 처음 만난 폴더가 하네스 루트입니다. 홈 폴더에 닿으면 멈추고, 홈 폴더 자체는 검사하지 않습니다. 대화에 자동으로 실린 CLAUDE.md에는 HTML 주석이 지워져 있으므로 그것으로 판단하지 않습니다. 아래의 기록 파일 경로와 `<루트>`는 모두 이 하네스 루트를 기준으로 합니다.

- 찾음: 2단계로 갑니다.
- 못 찾음: **대체 브리핑**을 합니다. 현재 폴더를 `<루트>`로 삼아 README는 Read 도구로, 기존 문서(docs/, NOTES 등)는 Glob 도구로 목록을 찾아 Read 도구로 읽고, 3단계 스크립트에 둘째 인자 `10`을 붙여 최근 기록 10줄을 봅니다. 프로젝트가 무엇이고 최근 무슨 일이 있었는지 4단계 형식으로 요약하되, 읽지 못한 항목은 "없음"으로 둡니다. 끝에 "하네스를 켜려면 /hs"를 한 줄 안내하고 5단계로 갑니다. 하네스 파일을 만들거나 /hs를 강요하지 않습니다.

### 2. 컨텍스트 로드

WHY: 각 파일은 다른 종류의 기억이다. 필요한 부분만 읽어야 빠르면서도 맥락이 빠지지 않는다.

5개 파일을 차례로 읽되, 없는 파일은 건너뜁니다. 전체 내용이 아니라 아래 부분만 읽습니다(Stats Extraction).

1. **CLAUDE.md** → 첫 `#` 제목(프로젝트 이름). 대화에 자동으로 실렸다고 가정하지 않습니다(Cowork는 연결한 폴더의 CLAUDE.md를 자동으로 싣지 않습니다). `## 원칙`, `## 기록 파일 다루는 법`, `## 프로젝트 규칙`의 내용이 대화에 보이지 않으면 있는 섹션을 직접 읽습니다. 이 내용은 브리핑에 넣지 않고 이후 작업에서 따르기만 합니다.
2. **일지 파일** → JOURNAL.md가 있으면 그것을, 없고 하네스 형식 MEMORY.md(첫 줄이 `— 메모리`로 끝남)가 있으면 그것을 읽습니다. "마지막 세션" 전체(날짜, 요약, 다음 할 일 하위 목록)와 "의사결정 이력" 표 마지막 3행의 "결정" 칸을 읽습니다. MEMORY.md를 읽었다면 브리핑 끝에 "이 프로젝트의 기록 파일은 옛 형식(v1)이에요. /hs로 v2 업데이트할 수 있어요."를 한 줄 붙입니다.
3. **ERROR.md** → "미해결" 표의 행 수와 가장 오래된 날짜. 같은 유형 태그가 3건 이상이면 Circuit Breaker 경고: "⚠ [유형] 에러가 [N]건 쌓여 있습니다. 다른 접근이 필요할 수 있어요."
4. **ISSUE.md** → "미해결" 표의 행 수
5. **WIKI.md** → "목차" 목록의 제목만 (본문은 읽지 않음)

표의 행 수를 셀 때 표 머리, 구분선, HTML 주석 줄은 세지 않습니다.

### 3. git과 위임 작업 상태

WHY: 비개발자가 git을 의식하지 않아도 변경 상태가 보여야 한다. 확인을 스크립트 하나로 묶어야 권한 확인 창이 뜨지 않고, 명령 하나가 실패해도 나머지 결과를 받을 수 있다.

아래 한 줄만 단독으로 실행합니다. `<루트>`는 하네스 루트(대체 브리핑이면 현재 폴더)의 실제 경로로 바꿉니다.

```bash
bash "${CLAUDE_SKILL_DIR}/scripts/status.sh" "<루트>"
```

경로에 `${CLAUDE_SKILL_DIR}`가 치환되지 않은 채 보이면 이 SKILL.md와 같은 폴더의 `scripts/status.sh`를 씁니다. bash가 없어 실행할 수 없거나 스크립트가 머리말 없이 오류로 끝나면 현재 폴더에서 `-C` 없이 이 모양 그대로 `git rev-parse --show-toplevel`, `git log --oneline -3`(대체 브리핑은 `-10`), `git status --short -uall -- "<루트>"`를 따로 실행하고, `.planning/STATE.md`와 `.planning/BLOCKERS.md`는 있으면 Read로 읽습니다.

결과는 이렇게 읽습니다.
- `[git]`에 `not a git repository`가 나오면 "(버전 관리 꺼져 있음. /hs 로 켤 수 있어요)"로 표시합니다.
- `[기록]`에 `does not have any commits yet`이 나오면 "(아직 기록 없음)"으로 표시합니다.
- `[변경]`의 숫자는 아직 커밋하지 않은 변경 개수입니다. `확인 못 함`이 나오면(저장소인데 git 상태를 읽지 못함) 브리핑에 "커밋 안 된 변경: 확인 못 함"으로 적습니다.
- `[위임]`은 `.planning/STATE.md`가 있을 때만 나옵니다. 작업명과 갱신일을 읽고(`작업: ... | 갱신: ...` 줄이 있으면 그 값, 없으면 첫 제목), 끝에 `.planning/STATE.md` 경로가 한 줄 더 나오면 마지막 수정이 24시간을 넘은 것이므로 "(오래됨)"을 붙입니다. 아무것도 없으면 브리핑에서 위임 작업 줄을 뺍니다.
- `[차단]`의 숫자는 `.planning/BLOCKERS.md`의 미해결 항목 수입니다. 0이면 뺍니다.

### 4. 브리핑 출력

구조화된 요약을 출력한다:

```
━━━━━━━━━━━━━━━━━━━━━━
체크인: [프로젝트명]

지난 세션: [일지 요약 또는 "첫 세션입니다"] ([날짜])
다음 할 일: [목록 또는 "정해진 것 없음"]
최근 결정: [의사결정 이력 마지막 3개의 "결정" 칸 또는 "없음"]

미해결 이슈: [N개 또는 "없음"]
미해결 에러: [N개 또는 "없음"] [가장 오래된: N일 전]
[Circuit Breaker 경고가 있으면 여기에]

WIKI 목차: [제목들. 많으면 앞 5개와 전체 개수 / "없음"]
진행 중이던 위임 작업: [작업명 (갱신일) (오래됨)] · 차단 [N개]   ← .planning이 없으면 이 줄을 뺌

커밋 안 된 변경: [N개 또는 "없음"]
최근 기록:
  [git log 3줄 / "(아직 기록 없음)" / "(버전 관리 꺼져 있음. /hs 로 켤 수 있어요)"]
━━━━━━━━━━━━━━━━━━━━━━
```

### 5. 선택지 제안 → 대기

브리핑을 글로 출력한 뒤, 선택지 질문 도구로 묻고 사용자의 선택을 기다립니다. 질문 문장 자체에 브리핑 핵심을 넣어 글을 못 봐도 알 수 있게 합니다: "지난 세션(<날짜>): <요약 한 줄> · 다음 할 일 N개 · 미해결 이슈 N · 에러 N — 무엇을 할까요?" 번호 목록 글로 묻는 것은 도구가 없을 때만입니다. 자동으로 작업을 시작하지 않습니다.
- 이어서 작업 (다음 할 일이 있으면 첫 항목을 함께 표시)
- 새로 시작
- 지난 작업 먼저 정리 (/co)

## 확인 사항

- [ ] 하네스 표식을 Read 도구로 파일에서 직접 확인함 (자동으로 실린 CLAUDE.md로 판단하지 않음. 없으면 대체 브리핑만 하고 하네스 파일을 만들거나 /hs를 강요하지 않음)
- [ ] 기록 파일은 필요한 부분만 읽음 (일지 "마지막 세션"과 최근 결정 3개, ERROR.md·ISSUE.md 행 수와 Circuit Breaker, WIKI.md는 목차만)
- [ ] 상태 확인은 스크립트 한 줄로 실행함. 커밋이 없는 저장소는 "(아직 기록 없음)"으로 표시함
- [ ] 브리핑을 출력하고 선택지 질문으로 다음 행동을 물은 뒤 기다림 (자동 시작 안 함)
