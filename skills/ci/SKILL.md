# ci — 체크인

세션을 시작할 때 프로젝트 맥락을 로드하고 이전 작업 상태를 파악합니다.

## 언제 사용

- 새 세션을 시작할 때 (가장 먼저)
- 이전 작업을 이어서 할 때
- 프로젝트 상태를 확인하고 싶을 때

## 프로세스

### 1. 상태 감지

WHY: 하네스가 없으면 체크인할 수 없다. 사용자를 올바른 흐름으로 안내해야 한다.

CLAUDE.md 파일에서 `<!-- non-dev-harness:` 마커 프리픽스 확인:
- 마커 없음 → "하네스가 없습니다. /hs 로 먼저 세팅하세요." → 종료
- 마커 있음 → 계속

### 2. 컨텍스트 로드

WHY: 각 파일은 다른 종류의 기억. 모두 읽어야 완전한 맥락이 된다.

5개 파일을 순차로 읽되, 없는 파일은 무시한다. 전체 내용이 아니라 핵심만 추출 (Stats Extraction):

1. **CLAUDE.md** → 프로젝트 규칙 (이미 CC가 자동 로드, 확인용)
2. **MEMORY.md** → "마지막 세션" 섹션만 먼저 읽기. 세션 요약 + 다음 할 일 + 의사결정 개수
3. **ERROR.md** → 미해결 에러 개수만 카운트. 상세 내용은 필요 시 읽기
4. **ISSUE.md** → 미해결 이슈 개수만 카운트. 상세 내용은 필요 시 읽기
5. **WIKI.md** → 목차만 확인 (전체 읽기 금지 — 토큰 절약)

### 3. Git 상태

WHY: 비개발자가 git을 의식하지 않아도 변경 상태가 보여야 한다.

git repo인 경우:
- `git log --oneline -3` (최근 기록 3줄)
- `git status --short` (변경된 파일)

git repo가 아닌 경우:
- "(버전 관리 꺼져 있음. /hs 로 켤 수 있어요)"

Circuit Breaker: ERROR.md 미해결 테이블에서 같은 유형 태그가 3건 이상이면:
- "⚠ [유형] 에러가 [N]건 쌓여 있습니다. 다른 접근이 필요할 수 있어요."

### 4. 브리핑 출력

구조화된 요약을 출력한다:

```
━━━━━━━━━━━━━━━━━━━━━━
체크인: [프로젝트명]

지난 세션: [MEMORY.md 요약 또는 "첫 세션입니다"]
다음 할 일: [TODO 또는 "정해진 것 없음"]

미해결 이슈: [N개 또는 "없음"]
미해결 에러: [N개 또는 "없음"] [가장 오래된: N일 전]

최근 기록:
  [git log 3줄 또는 "(기록 없음)"]
━━━━━━━━━━━━━━━━━━━━━━
```

### 5. 선택지 제안 → 대기

다음 선택지를 제안하고 사용자 입력을 기다린다. 자동으로 작업을 시작하지 않는다.

"무엇을 할까요?"
- 이어서 작업 (다음 할 일이 있으면 표시)
- 새로 시작
- 지난 작업 먼저 정리 (/co)

## 흔한 실수

| 변명 | 현실 |
|------|------|
| "체크인 안 해도 작업할 수 있잖아" | 이전 맥락 없이 시작하면 같은 실수를 반복하거나 이미 한 결정을 다시 내림 |
| "파일 읽기가 토큰 낭비 아냐?" | Stats Extraction으로 카운트만 읽음. 전체 내용을 읽는 것보다 90% 절약 |
| "빨리 작업부터 시작하고 싶어" | 2분 브리핑이 2시간 재작업을 방지함 |

## 위험 신호

- [ ] 5개 파일을 전부 전체 읽기 시도 (카운트/요약만 읽어야 함)
- [ ] 브리핑 없이 바로 작업 시작
- [ ] 하네스 없는 프로젝트에서 강제 실행 시도
- [ ] WIKI.md 전체를 읽으려 함 (목차만 확인)

## 확인 사항

- [ ] CLAUDE.md 마커 확인 완료
- [ ] MEMORY.md "마지막 세션" 정보 로드됨
- [ ] ERROR.md, ISSUE.md 카운트 확인됨
- [ ] 브리핑 출력됨
- [ ] 사용자 입력 대기 중 (자동 시작 안 함)
