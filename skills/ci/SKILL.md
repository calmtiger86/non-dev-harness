# ci — 체크인

세션을 시작할 때 프로젝트 맥락을 로드하고 이전 작업 상태를 파악합니다.

## 언제 사용

- 새 세션을 시작할 때 (가장 먼저)
- 이전 작업을 이어서 할 때
- 프로젝트 상태를 확인하고 싶을 때

## 프로세스

### 1. 상태 감지

WHY: 하네스가 있으면 5개 기록 파일로, 없으면 프로젝트 자체 기록으로 브리핑한다. 하네스가 없는 프로젝트에서도 체크인은 쓸모가 있다.

현재 폴더부터 한 단계씩 위로 올라가며 각 폴더의 CLAUDE.md 첫 줄을 Read나 grep으로 파일에서 직접 읽습니다. 첫 줄이 `<!-- non-dev-harness:`로 시작하는 CLAUDE.md를 처음 만난 폴더가 하네스 루트입니다. 홈 폴더에 닿으면 멈추고, 홈 폴더 자체는 검사하지 않습니다. 대화에 자동으로 실린 CLAUDE.md에는 HTML 주석이 지워져 있으므로 그것으로 판단하지 않습니다. 아래의 기록 파일 경로와 `<루트>`는 모두 이 하네스 루트를 기준으로 합니다.

- 찾음: 2단계로 갑니다.
- 못 찾음: **대체 브리핑**을 합니다. 현재 폴더를 `<루트>`로 삼아 README와 기존 문서(docs/, NOTES 등)를 읽고, 3단계 명령을 `git log --oneline -10`으로 바꿔 실행합니다. 프로젝트가 무엇이고 최근 무슨 일이 있었는지 4단계 형식으로 요약하되, 읽지 못한 항목은 "없음"으로 둡니다. 끝에 "하네스를 켜려면 /hs"를 한 줄 안내하고 5단계로 갑니다. 하네스 파일을 만들거나 /hs를 강요하지 않습니다.

### 2. 컨텍스트 로드

WHY: 각 파일은 다른 종류의 기억이다. 필요한 부분만 읽어야 빠르면서도 맥락이 빠지지 않는다.

5개 파일을 차례로 읽되, 없는 파일은 건너뜁니다. 전체 내용이 아니라 아래 부분만 읽습니다(Stats Extraction).

1. **CLAUDE.md** → 첫 `#` 제목(프로젝트 이름). 대화에 자동으로 실렸다고 가정하지 않으며, 규칙 내용이 대화에 보이지 않으면 `## 프로젝트 규칙`도 읽습니다.
2. **MEMORY.md** → "마지막 세션" 전체(날짜, 요약, 다음 할 일 하위 목록)와 "의사결정 이력" 표 마지막 3행의 "결정" 칸
3. **ERROR.md** → "미해결" 표의 행 수와 가장 오래된 날짜. 같은 유형 태그가 3건 이상이면 Circuit Breaker 경고: "⚠ [유형] 에러가 [N]건 쌓여 있습니다. 다른 접근이 필요할 수 있어요."
4. **ISSUE.md** → "미해결" 표의 행 수
5. **WIKI.md** → "목차" 목록의 제목만 (본문은 읽지 않음)

표의 행 수를 셀 때 표 머리, 구분선, HTML 주석 줄은 세지 않습니다.

### 3. git과 위임 작업 상태

WHY: 비개발자가 git을 의식하지 않아도 변경 상태가 보여야 한다. 명령을 한 번에 묶어야 확인 창이 여러 번 뜨지 않고, 명령 하나가 실패해도 나머지 결과를 받을 수 있다.

아래 명령을 한 번의 Bash 호출로 실행합니다. `<루트>`는 실제 경로로 바꿉니다.

```bash
R="<루트>"
echo "[git]"; git rev-parse --show-toplevel 2>&1
echo "[기록]"; git log --oneline -3 2>&1
echo "[변경]"; git status --short -uall -- "$R" 2>/dev/null | wc -l
echo "[위임]"; head -n 5 "$R/.planning/STATE.md" 2>/dev/null && find "$R/.planning/STATE.md" -mmin +1440 2>/dev/null
echo "[차단]"; grep -E '^[-*] ' "$R/.planning/BLOCKERS.md" 2>/dev/null | grep -vic '^[-*] \[x\]'
true
```

결과는 이렇게 읽습니다.
- `[git]`에 `not a git repository`가 나오면 "(버전 관리 꺼져 있음. /hs 로 켤 수 있어요)"로 표시합니다.
- `[기록]`에 `does not have any commits yet`이 나오면 "(아직 기록 없음)"으로 표시합니다.
- `[변경]`의 숫자는 아직 커밋하지 않은 변경 개수입니다.
- `[위임]`은 `.planning/STATE.md`가 있을 때만 나옵니다. 작업명과 갱신일을 읽고(`작업: ... | 갱신: ...` 줄이 있으면 그 값, 없으면 첫 제목), 끝에 파일 경로가 한 줄 더 나오면 마지막 수정이 24시간을 넘은 것이므로 "(오래됨)"을 붙입니다. 아무것도 없으면 브리핑에서 위임 작업 줄을 뺍니다.
- `[차단]`의 숫자는 `.planning/BLOCKERS.md`의 미해결 항목 수입니다. 0이면 뺍니다.

### 4. 브리핑 출력

구조화된 요약을 출력한다:

```
━━━━━━━━━━━━━━━━━━━━━━
체크인: [프로젝트명]

지난 세션: [MEMORY.md 요약 또는 "첫 세션입니다"] ([날짜])
다음 할 일: [목록 또는 "정해진 것 없음"]
최근 결정: [의사결정 이력 마지막 3개의 "결정" 칸 또는 "없음"]

미해결 이슈: [N개 또는 "없음"]
미해결 에러: [N개 또는 "없음"] [가장 오래된: N일 전]
[Circuit Breaker 경고가 있으면 여기에]

WIKI 목차: [제목들. 많으면 앞 5개와 전체 개수 / "없음"]
진행 중이던 위임 작업: [작업명 (갱신일) (오래됨)] · 차단 [N개]   ← .planning이 없으면 이 줄을 뺌

커밋 안 된 변경: [N개 또는 "없음"]
최근 기록:
  [git log 3줄 / "(아직 기록 없음)" / "(버전 관리 꺼져 있음. /hs 로 켤 수 있어요)"]
━━━━━━━━━━━━━━━━━━━━━━
```

### 5. 선택지 제안 → 대기

다음 선택지를 제안하고 사용자 입력을 기다린다. 자동으로 작업을 시작하지 않는다.

"무엇을 할까요?"
- 이어서 작업 (다음 할 일이 있으면 표시)
- 새로 시작
- 지난 작업 먼저 정리 (/co)

## 흔한 실수

| 변명 | 현실 |
|------|------|
| "체크인 안 해도 작업할 수 있잖아" | 이전 맥락 없이 시작하면 같은 실수를 반복하거나 이미 한 결정을 다시 내림 |
| "파일 읽기가 토큰 낭비 아냐?" | Stats Extraction으로 필요한 부분만 읽음. 전체를 읽는 것보다 훨씬 적게 듦 |
| "빨리 작업부터 시작하고 싶어" | 2분 브리핑이 2시간 재작업을 방지함 |

## 위험 신호

- [ ] 하네스 표식을 자동으로 실린 CLAUDE.md로 판단함 (파일을 직접 읽지 않음)
- [ ] 5개 파일을 전부 전체 읽기 시도 (필요한 부분만 읽어야 함)
- [ ] 브리핑 없이 바로 작업 시작
- [ ] 하네스 없는 프로젝트에서 하네스 파일을 만들거나 /hs 를 강요함 (대체 브리핑만 한다)
- [ ] WIKI.md 본문을 읽으려 함 (목차만 확인)
- [ ] git 확인 명령을 여러 번에 나눠 실행함

## 확인 사항

- [ ] 하네스 표식을 파일에서 직접 확인함 (없으면 대체 브리핑)
- [ ] MEMORY.md "마지막 세션"과 최근 결정 3개 로드됨 (하네스 있을 때)
- [ ] ERROR.md, ISSUE.md 행 수와 Circuit Breaker 확인됨 (하네스 있을 때)
- [ ] 커밋이 없는 저장소는 "(아직 기록 없음)"으로 표시됨
- [ ] 브리핑 출력됨
- [ ] 사용자 입력 대기 중 (자동 시작 안 함)
